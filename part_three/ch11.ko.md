# Kan 확장 {#kan-extensions}

지금까지는 주로 범주 하나 또는 범주 쌍을 다루었다. 때로는 제약이 조금 심했다. 예를 들어 범주 *C*에서 극한을 정의할 때 뿔의 바탕이 되는 패턴의 템플릿으로 인덱스 범주 `I`를 도입했다. 뿔의 꼭짓점 템플릿으로 다른 자명한 범주를 도입하는 것이 타당했겠지만, 대신 `I`에서 `C`로 가는 상수 functor Δ<sub>c</sub>를 사용했다.

이 어색함을 고칠 때가 되었다. 범주 셋으로 극한을 정의하자. 인덱스 범주 *I*에서 *C*로 가는 functor `D`로 시작한다. 뿔의 밑면을 고르는 도형 functor다.

![](images/kan2.jpg)

새로 추가하는 범주는 객체 하나와 항등 사상 하나를 가진 **1**이다. *I*에서 이 범주로 가는 functor `K`는 하나뿐이다. 모든 객체를 **1**의 유일한 객체로, 모든 사상을 항등 사상으로 보낸다. **1**에서 *C*로 가는 임의의 functor `F`는 뿔의 잠재적인 꼭짓점을 고른다.

![](images/kan15.jpg)

뿔은 `F ∘ K`에서 `D`로 가는 자연 변환 `ε`다. `F ∘ K`는 원래 Δ<sub>c</sub>와 정확히 같은 일을 한다. 다음 도형이 이 변환을 보여 준다.

![](images/kan3-e1492120491591.jpg)

이제 그런 functor 가운데 "가장 좋은" `F`를 고르는 보편적 속성을 정의할 수 있다. 이 `F`는 **1**을 *C*에서 `D`의 극한인 객체로 보내고, `F ∘ K`에서 `D`로 가는 자연 변환 `ε`는 대응 사영을 제공한다. 이 보편 functor를 `K`를 따른 `D`의 오른쪽 Kan 확장이라고 하고 Ran<sub>K</sub>D로 나타낸다.

보편적 속성을 표현하자. 다른 뿔, 즉 다른 functor `F'`와 `F' ∘ K`에서 `D`로 가는 자연 변환 `ε'`이 있다고 하자.

![](images/kan31-e1492120512209.jpg)

Kan 확장 F = Ran<sub>K</sub>D가 존재하면 `F'`에서 그곳으로 가는 유일한 자연 변환 `σ`가 있어 `ε'`이 `ε`을 거쳐 다음처럼 인수분해되어야 한다.

<pre>ε' = ε . (σ ∘ K)</pre>

여기서 `σ ∘ K`는 두 자연 변환의 수평 합성이다. 그중 하나는 `K`의 항등 자연 변환이다. 이어서 이 변환을 `ε`과 수직 합성한다.

![](images/kan5.jpg)

*I*의 객체 `i`에 작용하는 성분으로 쓰면 다음을 얻는다.

<pre>ε'<sub>i</sub> = ε<sub>i</sub> ∘ σ <sub>K i</sub></pre>

이 경우 `σ`는 **1**의 유일한 객체에 대응하는 성분 하나만 가진다. 따라서 실제로 `F'`가 정의한 뿔의 꼭짓점에서 Ran<sub>K</sub>D가 정의한 보편 뿔의 꼭짓점으로 가는 유일한 사상이다. 가환 조건은 극한의 정의가 요구하는 것과 정확히 같다.

중요한 점은 자명한 범주 **1**을 임의의 범주 *A*로 자유롭게 바꿀 수 있고 오른쪽 Kan 확장의 정의가 그대로 유효하다는 것이다.

## 오른쪽 Kan 확장

functor `K::I->A`를 따른 functor `D::I->C`의 오른쪽 Kan 확장은 자연 변환과 함께 주어진 functor `F::A->C`, 즉 Ran<sub>K</sub>D다.

<pre>ε :: F ∘ K -> D</pre>

다른 모든 functor `F'::A->C`와 자연 변환:

<pre>ε' :: F' ∘ K -> D</pre>

에 대해 `ε'`을 인수분해하는 유일한 자연 변환:

<pre>σ :: F' -> F</pre>

가 존재한다.

<pre>ε' = ε . (σ ∘ K)</pre>

말이 길지만 다음 멋진 도형으로 그릴 수 있다.

![](images/kan7.jpg)

흥미로운 관점은 Kan 확장이 어떤 의미에서 "functor 곱셈"의 역처럼 작용한다는 것이다. 어떤 저자는 Ran<sub>K</sub>D에 `D/K`라는 표기까지 사용한다. 실제로 이 표기에서는 오른쪽 Kan 확장의 쌍대단위라고도 하는 `ε`의 정의가 단순한 약분처럼 보인다.

<pre>ε :: D/K ∘ K -> D</pre>

Kan 확장의 다른 해석도 있다. functor `K`가 범주 *I*를 *A* 안에 매장한다고 하자. 가장 단순한 경우 *I*는 *A*의 부분 범주일 수 있다. *I*를 *C*로 보내는 functor `D`가 있다. `D`를 *A* 전체에 정의된 functor `F`로 확장할 수 있을까? 이상적으로는 합성 `F ∘ K`가 `D`와 동형이어야 한다. 즉 `F`가 `D`의 정의역을 `A`까지 확장한다. 하지만 완전한 동형은 보통 지나친 요구이므로 그 절반, 즉 `F ∘ K`에서 `D`로 가는 한 방향 자연 변환 `ε`만으로도 충분하다. 왼쪽 Kan 확장은 다른 방향을 고른다.

![](images/kan6.jpg)
물론 극한의 예처럼 functor `K`가 객체에 대해 단사가 아니거나 hom-set에 대해 충실하지 않으면 매장 그림은 무너진다. 그 경우 Kan 확장은 잃은 정보를 최대한 잘 외삽하려 한다.

## 수반으로서의 Kan 확장

고정된 `K`에 대해 모든 `D`의 오른쪽 Kan 확장이 존재한다고 하자. 그러면 Ran<sub>K</sub> - 는 functor 범주 `[I, C]`에서 `[A, C]`로 가는 functor다. 여기서 대시는 `D`의 자리다. 이 functor는 앞 합성 functor `-∘K`의 오른쪽 수반이다. 후자는 `[A, C]`의 functor를 `[I, C]`의 functor로 보낸다. 수반은 다음과 같다.

<pre>\[I, C\](F' ∘ K, D) ≅ \[A, C\](F', Ran<sub>K</sub>D)</pre>

`ε'`이라고 부른 모든 자연 변환에 `σ`라고 부른 유일한 자연 변환이 대응한다는 사실을 다시 쓴 것일 뿐이다.

![](images/kan92.jpg)

더 나아가 범주 *I*를 *C*와 같게 고르면 `D` 대신 항등 functor I<sub>C</sub>를 대입할 수 있다.

<pre>\[C, C\](F' ∘ K, I<sub>C</sub>) ≅ \[A, C\](F', Ran<sub>K</sub>I<sub>C</sub>)</pre>

이제 `F'`을 Ran<sub>K</sub>I<sub>C</sub>와 같게 고를 수 있다. 오른쪽에는 항등 자연 변환이 있고, 그에 대응해 왼쪽은 다음 자연 변환을 준다.

<pre>ε :: Ran<sub>K</sub>I<sub>C</sub> ∘ K -> I<sub>C</sub></pre>

수반의 쌍대단위와 매우 비슷하다.

<pre>Ran<sub>K</sub>I<sub>C</sub> ⊣ K</pre>

실제로 functor `K`를 따른 항등 functor의 오른쪽 Kan 확장으로 `K`의 왼쪽 수반을 계산할 수 있다. 여기에 조건이 하나 더 필요하다. 오른쪽 Kan 확장이 functor `K`에 의해 보존되어야 한다. 확장 보존은 `K`와 앞 합성한 functor의 Kan 확장을 계산한 결과가 원래 Kan 확장을 `K`와 앞 합성한 것과 같아야 한다는 뜻이다. 이 경우 조건은 다음으로 단순해진다.

<pre>K ∘ Ran<sub>K</sub>I<sub>C</sub> ≅ Ran<sub>K</sub>K</pre>

K로 나누는 표기를 사용하면 수반은 다음처럼 쓸 수 있다.

<pre>I/K ⊣ K</pre>

수반이 어떤 종류의 역을 설명한다는 직관을 확인해 준다. 보존 조건은 다음과 같다.

<pre>K ∘ I/K ≅ K/K</pre>

functor를 자기 자신을 따라 오른쪽 Kan 확장한 `K/K`를 codensity monad라고 한다.

수반 공식은 중요하다. 곧 end와 coend로 Kan 확장을 계산할 수 있음을 볼 것이며, 이는 오른쪽과 왼쪽 수반을 찾는 실용적인 수단을 준다.

## 왼쪽 Kan 확장

왼쪽 Kan 확장을 주는 쌍대 구성이 있다. 직관을 얻으려고 쌍대극한의 정의에서 시작해 한 원소 범주 **1**을 사용하도록 재구성할 수 있다. functor `D::I->C`로 밑면을 만들고 functor `F::1->C`로 꼭짓점을 골라 쌍대뿔을 만든다.

![](images/kan81.jpg)

쌍대뿔의 옆면인 주입들은 `D`에서 `F ∘ K`로 가는 자연 변환 `η`의 성분이다.

![](images/kan10a.jpg)

쌍대극한은 보편 쌍대뿔이다. 따라서 다른 모든 functor `F'`과 자연 변환:

<pre>η' :: D -> F'∘ K</pre>

![](images/kan10b.jpg)

에 대해 `F`에서 `F'`으로 가는 유일한 자연 변환 `σ`가 있고:

![](images/kan14.jpg)

다음을 만족한다.

<pre>η' = (σ ∘ K) . η</pre>

다음 도형이 이를 보여 준다.
![](images/kan112.jpg)

한 원소 범주 **1**을 *A*로 바꾸면 이 정의는 자연스럽게 Lan<sub>K</sub>D로 나타내는 왼쪽 Kan 확장의 정의로 일반화된다.
![](images/kan12.jpg)

자연 변환:

<pre>η :: D -> Lan<sub>K</sub>D ∘ K</pre>

을 왼쪽 Kan 확장의 단위라고 한다.

앞처럼 자연 변환 사이의 일대일 대응:

<pre>η' = (σ ∘ K) . η</pre>

을 수반으로 다시 쓸 수 있다.

<pre>\[A, C\](Lan<sub>K</sub>D, F') ≅ \[I, C\](D, F' ∘ K)</pre>

다시 말해 왼쪽 Kan 확장은 `K`와의 앞 합성에 대한 왼쪽 수반이고 오른쪽 Kan 확장은 오른쪽 수반이다.

항등 functor의 오른쪽 Kan 확장으로 `K`의 왼쪽 수반을 계산할 수 있었던 것처럼, 항등 functor의 왼쪽 Kan 확장은 `K`의 오른쪽 수반이다. 여기서 `η`가 수반의 단위다.

<pre>K ⊣ Lan<sub>K</sub>I<sub>C</sub></pre>

두 결과를 합치면 다음을 얻는다.

<pre>Ran<sub>K</sub>I<sub>C</sub> ⊣ K ⊣ Lan<sub>K</sub>I<sub>C</sub></pre>

## End로 나타낸 Kan 확장

Kan 확장의 진짜 힘은 end와 coend로 계산할 수 있다는 데서 나온다. 단순하게 하려고 대상 범주 *C*가 **Set**인 경우로 제한하지만 공식은 임의의 범주로 확장할 수 있다.

Kan 확장으로 functor의 원래 정의역 밖까지 작용을 확장한다는 발상을 다시 보자. `K`가 *I*를 *A* 안에 매장한다고 하자. functor `D`는 *I*를 **Set**으로 보낸다. `K`의 이미지에 있는 모든 객체 `a`, 즉 `a = K i`에 대해 확장된 functor가 `a`를 `D i`로 보낸다고 말할 수 있다. 문제는 `K`의 이미지 밖에 있는 *A*의 객체를 어떻게 할지다. 그런 객체 각각은 `K` 이미지의 모든 객체와 많은 사상으로 연결될 수 있고 functor는 이를 보존해야 한다. 객체 `a`에서 `K`의 이미지로 가는 모든 사상은 hom-functor가 나타낸다.

```haskell
A(a, K -)
```

![](images/kan13.jpg)
이 hom-functor는 두 functor의 합성이라는 점에 주목하자.

<pre>A(a, K -) = A(a, -) ∘ K</pre>

오른쪽 Kan 확장은 functor 합성의 오른쪽 수반이다.

<pre>\[I, Set\](F' ∘ K, D) ≅ \[A, Set\](F', Ran<sub>K</sub>D)</pre>

`F'`을 hom-functor로 바꾸면 어떻게 되는지 보자.

<pre>\[I, Set\](A(a, -) ∘ K, D) ≅ \[A, Set\](A(a, -), Ran<sub>K</sub>D)</pre>

합성을 인라인으로 넣으면:

<pre>\[I, Set\](A(a, K -), D) ≅ \[A, Set\](A(a, -), Ran<sub>K</sub>D)</pre>

요네다 보조정리로 오른쪽을 줄일 수 있다.

<pre>\[I, Set\](A(a, K -), D) ≅ Ran<sub>K</sub>D a</pre>

자연 변환 집합을 end로 다시 쓰면 오른쪽 Kan 확장의 편리한 공식을 얻는다.

<pre>Ran<sub>K</sub>D a ≅ ∫<sub>i</sub> Set(A(a, K i), D i)</pre>

왼쪽 Kan 확장에는 coend로 표현한 비슷한 공식이 있다.

<pre>Lan<sub>K</sub>D a = ∫<sup>i</sup> A(K i, a) × D i</pre>

실제로 functor 합성의 왼쪽 수반임을 보여 이 사실을 확인하자.

<pre>\[A, Set\](Lan<sub>K</sub>D, F') ≅ \[I, Set\](D, F'∘ K)</pre>

왼쪽에 공식을 대입한다.

<pre>\[A, Set\](∫<sup>i</sup> A(K i, -) × D i, F')</pre>

자연 변환의 집합이므로 end로 다시 쓸 수 있다.

<pre>∫<sub>a</sub> Set(∫<sup>i</sup> A(K i, a) × D i, F'a)</pre>

hom-functor의 연속성을 사용해 coend를 end로 바꾼다.

<pre>∫<sub>a</sub> ∫<sub>i</sub> Set(A(K i, a) × D i, F'a)</pre>

곱-지수 수반을 사용할 수 있다.

<pre>∫<sub>a</sub> ∫<sub>i</sub> Set(A(K i, a), (F'a)<sup>D i</sup>)</pre>

지수는 대응하는 hom-set과 동형이다.

<pre>∫<sub>a</sub> ∫<sub>i</sub> Set(A(K i, a), A(D i, F'a))</pre>

Fubini 정리는 두 end의 순서를 바꾸게 해 준다.

<pre>∫<sub>i</sub> ∫<sub>a</sub> Set(A(K i, a), A(D i, F'a))</pre>

안쪽 end는 두 functor 사이의 자연 변환 집합을 나타내므로 요네다 보조정리를 사용할 수 있다.

<pre>∫<sub>i</sub> A(D i, F'(K i))</pre>

실제로 증명하려던 수반 오른쪽을 이루는 자연 변환 집합이다.

<pre>\[I, Set\](D, F'∘ K)</pre>

end, coend, 요네다 보조정리를 사용하는 이런 계산은 end의 "미적분"에서 전형적이다.

## 하스켈의 Kan 확장

Kan 확장의 end/coend 공식은 하스켈로 쉽게 옮길 수 있다. 오른쪽 확장부터 시작하자.

<pre class="language-haskell">
Ran<sub>K</sub>D a ≅ ∫<sub>i</sub> Set(A(a, K i), D i)
</pre>

end는 전칭 한정자로, hom-set은 함수 타입으로 바꾼다.

```haskell
newtype Ran k d a = Ran (forall i. (a -> k i) -> d i)
```

이 정의를 보면 `Ran`은 함수를 적용할 타입 `a`의 값과 functor `k`, `d` 사이의 자연 변환을 담아야 함이 분명하다. 예를 들어 `k`가 트리 functor이고 `d`가 리스트 functor이며 `Ran Tree [] String`이 주어졌다고 하자. 다음 함수를 전달하면:

```haskell
f :: String -> Tree Int
```

`Int` 리스트를 돌려받는다. 오른쪽 Kan 확장은 함수로 트리를 만든 다음 리스트로 다시 포장한다. 문자열에서 parse 트리를 만드는 parser를 넘기면 트리의 깊이 우선 순회에 대응하는 리스트를 얻을 수 있다.

functor `d`를 항등 functor로 바꾸면 오른쪽 Kan 확장으로 주어진 functor의 왼쪽 수반을 계산할 수 있다. functor `k`의 왼쪽 수반은 다음 타입의 다형 함수 집합으로 표현된다.

```haskell
forall i. (a -> k i) -> i
```

`k`가 모노이드 범주의 망각 functor라고 하자. 전칭 한정자는 모든 모노이드에 걸친다. 하스켈에서는 모노이드 법칙을 표현할 수 없지만 다음은 결과인 자유 functor의 괜찮은 근사다. 망각 functor `k`는 객체에 대한 항등이다.

```haskell
type Lst a = forall i. Monoid i => (a -> i) -> i
```

예상대로 자유 모노이드, 즉 하스켈 리스트를 만든다.

```haskell
toLst :: [a] -> Lst a
toLst as = \f -> foldMap f as

fromLst :: Lst a -> [a]
fromLst f = f (\a -> [a])
```

왼쪽 Kan 확장은 coend다.

<pre>Lan<sub>K</sub>D a = ∫<sup>i</sup> A(K i, a) × D i</pre>

따라서 존재 한정자로 옮겨진다. 기호로는:

<pre>Lan k d a = exists i. (k i -> a, d i)</pre>

GADT 또는 전칭 한정된 데이터 생성자로 하스켈에서 인코딩할 수 있다.

```haskell
data Lan k d a = forall i. Lan (k i -> a) (d i)
```

이 데이터 구조는 어떤 알 수 없는 `i`의 컨테이너를 받아 `a`를 만드는 함수와 그 `i`의 컨테이너를 담는다. `i`가 무엇인지 모르므로 이 구조로 할 수 있는 일은 `i`의 컨테이너를 꺼내 자연 변환을 사용해 functor `k`가 정의하는 컨테이너로 다시 포장하고, 함수를 호출해 `a`를 얻는 것뿐이다. 예를 들어 `d`가 트리이고 `k`가 리스트라면 트리를 직렬화하고 결과 리스트로 함수를 호출해 `a`를 얻는다.

왼쪽 Kan 확장으로 functor의 오른쪽 수반을 계산할 수 있다. 곱 functor의 오른쪽 수반이 지수임을 아니 Kan 확장으로 구현해 보자.

<pre>type Exp a b = Lan ((,) a) I b</pre>

실제로 다음 함수 쌍이 증명하듯 함수 타입과 동형이다.

```haskell
toExp :: (a -> b) -> Exp a b
toExp f = Lan (f . fst) (I ())

fromExp :: Exp a b -> (a -> b)
fromExp (Lan f (I x)) = \a -> f (a, x)
```

일반적인 경우에서 설명한 단계를 수행했다. (1) `x`의 컨테이너, 여기서는 자명한 항등 컨테이너와 함수 `f`를 꺼내고, (2) 항등 functor와 쌍 functor 사이 자연 변환으로 컨테이너를 다시 포장하고, (3) 함수 `f`를 호출했다.

## 자유 Functor

Kan 확장의 흥미로운 응용은 자유 functor 구성이다. 다음 실용적인 문제의 해법이다. 객체의 사상인 타입 생성자가 있다고 하자. 이 타입 생성자를 바탕으로 functor를 정의할 수 있을까? 즉 이 타입 생성자를 완전한 endofunctor로 확장하는 사상의 사상을 정의할 수 있을까?

핵심 관찰은 타입 생성자를 정의역이 이산 범주인 functor로 설명할 수 있다는 것이다. 이산 범주에는 항등 사상 이외의 사상이 없다. 범주 *C*가 주어지면 항등이 아닌 모든 사상을 버려 이산 범주 *|C|*를 언제나 구성할 수 있다. *|C|*에서 *C*로 가는 functor `F`는 단순한 객체의 사상, 즉 하스켈의 타입 생성자다. *|C|*를 *C*에 주입하는 표준 functor `J`도 있다. 객체와 항등 사상에 대한 항등이다. `J`를 따른 `F`의 왼쪽 Kan 확장이 존재하면 *C*에서 *C*로 가는 functor다.

<pre>Lan<sub>J</sub> F a = ∫<sup>i</sup> C(J i, a) × F i</pre>

`F`를 바탕으로 한 자유 functor라고 한다.

하스켈에서는 다음처럼 쓴다.

```haskell
data FreeF f a = forall i. FMap (i -> a) (f i)
```

실제로 모든 타입 생성자 `f`에 대해 `FreeF f`는 functor다.

```haskell
instance Functor (FreeF f) where
  fmap g (FMap h fi) = FMap (g . h) fi
```

보듯 자유 functor는 함수와 그 인자를 함께 기록해 함수 끌어올리기를 흉내 낸다. 끌어올린 함수의 합성을 기록하며 축적하고 functor 법칙은 자동으로 만족된다. 이 구성은 논문 [Freer Monads, More Extensible Effects](http://okmij.org/ftp/Haskell/extensible/more.pdf)에 사용되었다.

같은 목적으로 오른쪽 Kan 확장을 사용할 수도 있다.

```haskell
newtype FreeF f a = FreeF (forall i. (a -> i) -> f i)
```

실제로 functor임은 쉽게 확인할 수 있다.

```haskell
instance Functor (FreeF f) where
    fmap g (FreeF r) = FreeF (\bi -> r (bi . g))
```
