# 표현 가능 Functor {#representable-functors}

집합에 대해 이야기할 때가 되었다. 수학자는 집합론과 애증 관계에 있다. 집합론은 적어도 예전에는 수학의 어셈블리 언어였다. 범주론은 어느 정도 집합론에서 벗어나려 한다. 예를 들어 모든 집합의 집합은 존재하지 않지만 모든 집합의 범주 **Set**은 존재한다. 좋은 일이다. 한편 범주의 임의의 두 객체 사이 사상은 집합을 이룬다고 가정하며 이를 hom-set이라고까지 불렀다. 공평하게 말하면 사상이 집합을 이루지 않고 다른 범주의 객체가 되는 범주론의 분야도 있다. hom-set 대신 hom-객체를 사용하는 범주를 *풍성한* 범주라고 한다. 하지만 여기서는 오래되고 익숙한 hom-set을 가진 범주만 다룬다.

집합은 범주론적 객체 바깥에서 얻을 수 있는 가장 특징 없는 덩어리에 가깝다. 원소가 있지만 그 원소에 관해 할 수 있는 말은 별로 없다. 유한 집합이면 원소를 셀 수 있고, 무한 집합도 기수를 사용해 어느 정도 셀 수 있다. 예를 들어 자연수 집합과 실수 집합은 둘 다 무한하지만 자연수 집합이 더 작다. 놀랍게도 유리수 집합은 자연수 집합과 크기가 같다.

그 밖에 집합에 관한 모든 정보는 집합 사이의 함수, 특히 동형이라는 가역 함수로 인코딩할 수 있다. 모든 실용적인 목적에서 동형인 집합은 동일하다. 기초론 수학자의 분노를 부르기 전에 등식과 동형의 구별은 근본적으로 중요하다고 설명하겠다. 최신 수학 분야인 호모토피 타입 이론(HoTT)의 주요 관심사 가운데 하나이기도 하다. HoTT를 언급하는 이유는 계산에서 영감을 받은 순수 수학 이론이고, 주요 주창자 Vladimir Voevodsky가 Coq 정리 증명기를 연구하다 큰 깨달음을 얻었기 때문이다. 수학과 프로그래밍의 상호작용은 양방향이다.

집합에 관한 중요한 교훈은 서로 다른 종류의 원소를 가진 집합도 비교해도 된다는 것이다. 예를 들어 어떤 자연 변환 집합이 어떤 사상 집합과 동형이라고 말할 수 있다. 집합은 그저 집합이기 때문이다. 여기서 동형은 한 집합의 자연 변환마다 다른 집합에 유일한 사상이 있고 그 역도 성립해 서로 짝지을 수 있다는 뜻일 뿐이다. 서로 다른 범주의 객체라면 사과와 오렌지를 비교할 수 없지만 사과 집합과 오렌지 집합은 비교할 수 있다. 범주론적 문제를 집합론적 문제로 바꾸면 필요한 통찰을 얻거나 귀중한 정리를 증명할 수 있을 때가 많다.

## Hom Functor

모든 범주에는 **Set**으로 가는 표준적인 사상족이 갖추어져 있다. 이 사상들은 실제로 functor이므로 범주의 구조를 보존한다. 하나를 만들어 보자.

*C*의 객체 `a` 하나를 고정하고 역시 *C*에 있는 다른 객체 `x`를 고르자. hom-set `C(a, x)`는 집합, 즉 **Set**의 객체다. `a`는 고정한 채 `x`를 바꾸면 `C(a, x)`도 **Set** 안에서 변한다. 따라서 `x`에서 **Set**으로 가는 사상이 있다.

![](images/hom-set2.jpg)

hom-set을 두 번째 인자에 대한 사상으로 보고 있음을 강조할 때 다음 표기를 사용한다.

```
C(a, -)
```

여기서 대시는 인자가 들어갈 자리다.

이 객체의 사상은 사상의 사상으로 쉽게 확장된다. *C*의 임의의 두 객체 `x`와 `y` 사이 사상 `f`를 보자. 방금 정의한 사상 아래에서 `x`는 집합 `C(a, x)`로, `y`는 `C(a, y)`로 보내진다. 이 사상이 functor가 되려면 `f`는 두 집합 사이의 함수로 보내져야 한다.

```haskell
C(a, x) -> C(a, y)
```

이 함수를 각 인자에 대해 점별로 정의하자. 인자로 `C(a, x)`의 임의의 원소 `h`를 고른다. 사상의 끝과 시작이 맞으면 합성할 수 있다. 마침 `h`의 대상과 `f`의 원천이 맞으므로 그 합성:

```
f ∘ h :: a -> y
```

은 `a`에서 `y`로 가는 사상이고 따라서 `C(a, y)`의 원소다.

![Hom Functor](images/hom-functor.jpg)

`f`의 이미지 역할을 할 `C(a, x)`에서 `C(a, y)`로 가는 함수를 찾았다. 혼동할 위험이 없으면 이 끌어올린 함수를 다음처럼 쓴다.

```
C(a, f)
```

사상 `h`에 대한 작용은 다음과 같다.

```
C(a, f) h = f ∘ h
```

이 구성은 모든 범주에서 작동하므로 하스켈 타입의 범주에서도 작동한다. 하스켈에서 hom-functor는 `Reader` functor로 더 잘 알려져 있다.

```haskell
type Reader a x = a -> x
```

```haskell
instance Functor (Reader a) where
    fmap f h = f . h
```

이제 hom-set의 원천 대신 대상을 고정하면 어떻게 되는지 생각하자. 즉 다음 사상도 functor인지 묻는다.

```
C(-, a)
```

functor이기는 하지만 공변이 아니라 반변이다. `C(a, -)`에서는 앞에 합성했지만, 사상 끝을 같은 방식으로 맞추면 이번에는 `f`를 뒤에 합성하게 되기 때문이다.

하스켈에서 이 반변 functor를 이미 보았으며 `Op`라고 불렀다.

```haskell
type Op a x = x -> a
```

```haskell
instance Contravariant (Op a) where
    contramap f h = h . f
```

마지막으로 두 객체를 모두 바꾸면 첫 인자에는 반변이고 둘째 인자에는 공변인 profunctor `C(-, =)`을 얻는다. 두 인자가 독립적으로 변할 수 있음을 강조하려고 두 번째 자리에는 다른 기호를 쓴다. functoriality를 이야기할 때 이 profunctor를 이미 보았다.

```haskell
instance Profunctor (->) where
  dimap ab cd bc = cd . bc . ab
  lmap = flip (.)
  rmap = (.)
```

중요한 교훈은 모든 범주에서 객체를 hom-set으로 보내는 사상이 functorial하다는 것이다. 반변성은 반대 범주에서 출발하는 사상과 동등하므로 이를 간결하게 다음처럼 쓸 수 있다.

<pre>
C(-, =) :: C<sup>op</sup> × C -> Set
</pre>

## 표현 가능 Functor

*C*의 객체 `a`를 고를 때마다 *C*에서 **Set**으로 가는 functor를 얻음을 보았다. **Set**으로 가는 이런 구조 보존 사상을 흔히 *표현*이라고 한다. *C*의 객체와 사상을 **Set**의 집합과 함수로 표현한다.

functor `C(a, -)` 자체를 표현 가능하다고 부르기도 한다. 더 일반적으로 어떤 `a`를 골랐을 때 hom-functor와 자연 동형인 모든 functor `F`를 *표현 가능*하다고 한다. `C(a, -)`가 **Set** 값을 가지므로 그런 functor 역시 반드시 **Set** 값을 가진다.

앞에서 동형인 집합을 흔히 동일한 것으로 생각한다고 말했다. 더 일반적으로 범주에서 동형인 *객체*를 동일하다고 생각한다. 객체에는 사상을 통해 다른 객체 및 자기 자신과 맺는 관계 외에 구조가 없기 때문이다.

예를 들어 앞에서 집합으로 처음 모델링한 모노이드의 범주 **Mon**을 이야기했다. 다만 그 집합의 모노이드 구조를 보존하는 함수만 사상으로 고르도록 조심했다. 따라서 **Mon**의 두 객체가 동형, 즉 그 사이에 가역 사상이 있으면 구조가 정확히 같다. 바탕이 되는 집합과 함수를 들여다보면 한 모노이드의 단위 원소가 다른 모노이드의 단위로 보내지고 두 원소의 곱이 그 이미지들의 곱으로 보내짐을 볼 수 있다.

같은 추론을 functor에 적용할 수 있다. 두 범주 사이 functor들은 자연 변환을 사상으로 하는 범주를 이룬다. 따라서 두 functor 사이에 가역 자연 변환이 있으면 동형이고 동일하다고 생각할 수 있다.

이 관점에서 표현 가능 functor의 정의를 분석하자. `F`가 표현 가능하려면 *C*의 객체 `a`, `C(a, -)`에서 `F`로 가는 자연 변환 α, 반대 방향의 자연 변환 β가 있고 그 합성이 항등 자연 변환이어야 한다.

객체 `x`에서 α의 성분을 보자. **Set**의 함수다.

<pre>
α<sub>x</sub> :: C(a, x) -> F x

</pre>

이 변환의 자연성 조건은 `x`에서 `y`로 가는 임의의 사상 `f`에 대해 다음 도형이 가환한다고 말한다.

<pre>
F f ∘ α<sub>x</sub> = α<sub>y</sub> ∘ C(a, f)
</pre>

하스켈에서는 자연 변환을 다형 함수로 바꾼다.

```haskell
alpha :: forall x. (a -> x) -> F x
```

`forall` 한정자는 선택 사항이다. 자연성 조건:

```
fmap f . alpha = alpha . fmap f
```

은 매개변수성 때문에 자동으로 만족한다. 앞에서 언급한 공짜 정리 가운데 하나다. 왼쪽 `fmap`은 functor `F`가, 오른쪽은 reader functor가 정의한다. reader의 `fmap`은 함수의 앞 합성일 뿐이므로 더 명시적으로 쓸 수 있다. `C(a, x)`의 원소 `h`에 작용시키면 자연성 조건은 다음으로 단순해진다.

```haskell
fmap f (alpha h) = alpha (f . h)
```

다른 변환 `beta`는 반대 방향으로 간다.

```haskell
beta :: forall x. F x -> (a -> x)
```

자연성 조건을 지켜야 하고 α의 역이어야 한다.

```
α ∘ β = id = β ∘ α
```

`C(a, -)`에서 임의의 **Set** 값 functor로 가는 자연 변환은 언제나 존재하지만 반드시 가역인 것은 아님을 나중에 요네다 보조정리에서 보겠다.

리스트 functor와 `a`로서의 `Int`를 사용한 하스켈 예를 보자. 다음 자연 변환이 그 역할을 한다.

```haskell
alpha :: forall x. (Int -> x) -> [x]
alpha h = map h [12]
```

임의로 수 12를 골라 한 원소 리스트를 만들었다. 함수 `h`를 이 리스트에 `fmap`하면 `h`가 반환하는 타입의 리스트를 얻는다. 실제로 정수 리스트의 수만큼 이런 변환이 있다.

자연성 조건은 `map`, 즉 리스트 버전 `fmap`의 합성 가능성과 동등하다.

```haskell
map f (map h [12]) = map (f . h) [12]
```

하지만 역변환을 찾으려면 임의 타입 `x`의 리스트에서 `x`를 반환하는 함수로 가야 한다.

```haskell
beta :: forall x. [x] -> (Int -> x)
```

`head` 등을 사용해 리스트에서 `x`를 꺼낼 생각을 할 수 있지만 빈 리스트에서는 작동하지 않는다. 여기서 `Int` 대신 쓸 타입 `a`를 어떻게 골라도 작동하지 않는다. 따라서 리스트 functor는 표현 가능하지 않다.

하스켈 endofunctor를 컨테이너와 비슷하게 생각했던 것을 기억하는가? 같은 맥락에서 표현 가능 functor는 함수 호출의 메모이제이션된 결과를 저장하는 컨테이너라고 생각할 수 있다. 하스켈에서 hom-set의 원소는 함수일 뿐이다. 표현 객체, 즉 `C(a, -)`의 타입 `a`는 표로 만든 함수 값에 접근하는 키 타입이다. α라고 부른 변환은 `tabulate`, 그 역 β는 `index`라고 한다. 다음은 조금 단순화한 `Representable` 클래스 정의다.

```haskell
class Representable f where
   type Rep f :: *
   tabulate :: (Rep f -> x) -> f x
   index    :: f x -> Rep f -> x
```

여기서 `Rep f`라고 부르는 표현 타입 `a`가 `Representable` 정의의 일부라는 점에 주목하자. 별표는 `Rep f`가 타입 생성자나 더 특이한 kind가 아니라 타입이라는 뜻이다.

비어 있을 수 없는 무한 리스트, 즉 stream은 표현 가능하다.

```haskell
data Stream x = Cons x (Stream x)
```

`Integer`를 인자로 받는 함수의 메모이제이션된 값으로 생각할 수 있다. 엄밀히는 음수가 아닌 자연수를 써야 하지만 코드를 복잡하게 만들고 싶지 않았다.

그런 함수를 `tabulate`하려면 값의 무한 stream을 만든다. 하스켈이 지연 언어이기 때문에만 가능하며 값은 필요할 때 평가된다. `index`로 메모이제이션된 값에 접근한다.

```haskell
instance Representable Stream where
    type Rep Stream = Integer
    tabulate f = Cons (f 0) (tabulate (f . (+1)))
    index (Cons b bs) n = if n == 0 then b else index bs (n - 1)
```

임의의 반환 타입을 가진 함수족 전체를 하나의 메모이제이션 방식으로 다룰 수 있다는 점이 흥미롭다.

반변 functor의 표현 가능성도 비슷하게 정의하지만 `C(-, a)`의 두 번째 인자를 고정한다. 또는 C<sup>op</sup>(a, -)가 `C(-, a)`와 같으므로 *C*<sup>op</sup>에서 **Set**으로 가는 functor를 생각해도 된다.

표현 가능성에는 흥미로운 반전이 있다. 데카르트 닫힌 범주에서는 hom-set을 내부적으로 지수 객체로 취급할 수 있음을 기억하자. hom-set `C(a, x)`는 x<sup>a</sup>와 동등하고 표현 가능 functor `F`에 대해 다음처럼 쓸 수 있다.

<pre>
-<sup>a</sup> = F
</pre>

재미 삼아 양변에 로그를 취해 보자.

```haskell
a = log F
```

물론 순전히 형식적인 변환이지만 로그의 속성을 안다면 꽤 유용하다. 특히 곱 타입을 바탕으로 한 functor는 합 타입으로 표현할 수 있고, 합 타입 functor는 일반적으로 표현 가능하지 않다. 리스트 functor가 그 예다.

마지막으로 표현 가능 functor는 같은 것을 구현하는 두 방법, 즉 함수와 데이터 구조를 준다. 같은 키로 같은 값을 꺼내므로 내용이 정확히 같다. 이것이 앞서 말한 "같음"의 의미다. 자연 동형인 두 functor는 내용에 관한 한 동일하다. 한편 두 표현은 흔히 다르게 구현되어 성능 특성이 다를 수 있다. 메모이제이션은 성능 개선에 사용되어 실행 시간을 크게 줄일 수 있다. 같은 바탕 계산의 다른 표현을 만들 수 있다는 것은 실무에서 매우 가치 있다. 놀랍게도 범주론은 성능 자체에는 관심이 없으면서도 실용적 가치가 있는 대안 구현을 탐색할 기회를 풍부하게 제공한다.

## 연습문제

1. hom-functor가 *C*의 항등 사상을 **Set**의 대응하는 항등 함수로 보냄을 보여라.

2. `Maybe`가 표현 가능하지 않음을 보여라.

3. `Reader` functor는 표현 가능한가?

4. `Stream` 표현을 사용해 인자를 제곱하는 함수를 메모이제이션하라.

5. `Stream`의 `tabulate`와 `index`가 실제로 서로의 역임을 보여라. 힌트: 귀납법을 사용하라.

6. 다음 functor는 표현 가능하다.
```
Pair a = Pair a a
```
이를 표현하는 타입을 추측할 수 있는가? `tabulate`와 `index`를 구현하라.
