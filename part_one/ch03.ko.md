# 크고 작은 범주들 {#categories-great-and-small}

범주를 제대로 맛보려면 다양한 예를 공부해 보는 것이 좋다. 범주는 온갖 모양과 크기로 나타나며, 예상치 못한 곳에서 튀어나오기도 한다. 아주 단순한 것부터 시작해 보자.

## 객체가 없는 경우

가장 사소한 범주는 객체가 0개이고, 따라서 사상도 0개인 범주다. 그 자체로는 매우 쓸쓸한 범주지만, 다른 범주의 맥락에서는 중요할 수 있다. 예를 들어 모든 범주의 범주 안에서 그렇다. 그렇다, 그런 것도 있다. 공집합이 말이 된다고 생각한다면, 빈 범주라고 해서 안 될 이유가 있을까?

## 단순 그래프

객체들을 화살표로 연결하기만 해도 범주를 만들 수 있다. 임의의 방향 그래프에서 시작해 화살표를 더 추가함으로써 그것을 범주로 만든다고 상상할 수 있다. 먼저 각 노드에 항등 화살표를 추가한다. 그런 다음 한 화살표의 끝이 다른 화살표의 시작과 일치하는 임의의 두 화살표, 다시 말해 합성 가능한 임의의 두 화살표에 대해, 그 합성 역할을 할 새 화살표를 추가한다. 새 화살표를 추가할 때마다, 그 화살표와 다른 모든 화살표, 그리고 자기 자신과의 합성도 고려해야 한다. 보통은 무한히 많은 화살표를 얻게 되지만, 괜찮다.

이 과정을 보는 또 다른 방식은, 그래프의 각 노드마다 객체가 있고 합성 가능한 그래프 간선들의 모든 가능한 사슬을 사상으로 갖는 범주를 만들고 있다고 생각하는 것이다. 항등 사상은 길이가 0인 사슬의 특별한 경우로 생각할 수도 있다.

이런 범주를 주어진 그래프가 생성한 자유 범주라고 부른다. 이것은 자유 구성의 한 예다. 자유 구성이란 주어진 구조를 그 법칙, 여기서는 범주의 법칙을 만족하도록 최소한의 항목으로 확장해 완성하는 과정이다. 앞으로 더 많은 예를 보게 될 것이다.

## 순서

이제 완전히 다른 것을 보자. 사상이 객체들 사이의 관계인 범주, 즉 작거나 같다는 관계다. 이것이 정말 범주인지 확인해 보자. 항등 사상이 있는가? 모든 객체는 자기 자신보다 작거나 같다. 확인. 합성이 있는가? `a <= b`이고 `b <= c`이면 `a <= c`다. 확인. 합성은 결합적인가? 확인. 이런 관계를 가진 집합을 전순서가 아니라 전순서 비슷한 것, 즉 전순서(preorder)라고 부른다. 그러므로 전순서는 실제로 범주다.

더 강한 관계도 가질 수 있다. `a <= b`이고 `b <= a`이면 `a`와 `b`가 같아야 한다는 추가 조건을 만족하는 관계다. 이것을 부분 순서라고 부른다.

마지막으로, 임의의 두 객체가 어떤 방향으로든 서로 관계를 맺고 있어야 한다는 조건을 부과할 수 있다. 그러면 선형 순서 또는 전순서를 얻는다.

이 순서 집합들을 범주로 특징지어 보자. preorder는 임의의 객체 `a`에서 임의의 객체 `b`로 가는 사상이 많아야 하나뿐인 범주다. 이런 범주의 또 다른 이름은 얇은(thin) 범주다. preorder는 얇은 범주다.

범주 C에서 객체 `a`에서 객체 `b`로 가는 사상들의 집합을 hom-set이라고 부르며 C(a, b), 때로는 HomC(a, b)라고 쓴다. 따라서 preorder의 모든 hom-set은 비어 있거나 한 원소 집합이다. 여기에는 `a`에서 `a`로 가는 사상들의 집합인 C(a, a)도 포함된다. 어떤 preorder에서든 이 집합은 항등만을 포함하는 한 원소 집합이어야 한다. 다만 preorder에는 순환이 있을 수 있다. 부분 순서에서는 순환이 금지된다.

preorder, 부분 순서, 전체 순서를 알아볼 수 있는 것은 매우 중요하다. 정렬 때문이다. 퀵정렬, 버블 정렬, 병합 정렬 같은 정렬 알고리즘은 전체 순서에서만 올바르게 동작할 수 있다. 부분 순서는 위상 정렬을 사용해 정렬할 수 있다.

## 집합으로서의 모노이드

모노이드는 민망할 정도로 단순하지만 놀라울 만큼 강력한 개념이다. 기본 산술의 배후에 있는 개념이 바로 모노이드다. 덧셈과 곱셈은 둘 다 모노이드를 이룬다. 모노이드는 프로그래밍 어디에나 있다. 문자열, 리스트, 접을 수 있는 데이터 구조, 동시성 프로그래밍의 future, 함수형 반응형 프로그래밍의 이벤트 등으로 나타난다.

전통적으로 모노이드는 이항 연산을 가진 집합으로 정의된다. 이 연산에 요구되는 것은 결합적이어야 한다는 것과, 그 연산에 대해 단위처럼 행동하는 특별한 원소가 하나 있어야 한다는 것뿐이다.

예를 들어 0을 포함한 자연수는 덧셈에 대해 모노이드를 이룬다. 결합법칙은 다음을 뜻한다.

```
(a + b) + c = a + (b + c)
```

다시 말해 수를 더할 때 괄호를 생략할 수 있다.

중립 원소는 0이다. 다음이 성립하기 때문이다.

```
0 + a = a
```

그리고 다음도 성립한다.

```
a + 0 = a
```

두 번째 식은 덧셈이 교환적이기 때문에 중복이다. `a + b = b + a`이기 때문이다. 하지만 교환법칙은 모노이드 정의의 일부가 아니다. 예를 들어 문자열 연결은 교환적이지 않지만 모노이드를 이룬다. 참고로 문자열 연결의 중립 원소는 빈 문자열이다. 빈 문자열은 문자열의 어느 쪽에 붙여도 문자열을 바꾸지 않는다.

하스켈에서는 모노이드를 위한 타입 클래스를 정의할 수 있다. 중립 원소 `mempty`와 이항 연산 `mappend`가 있는 타입을 나타내는 클래스다.

```haskell
class Monoid m where
    mempty  :: m
    mappend :: m -> m -> m
```

두 인자 함수의 타입 시그니처 `m->m->m`은 처음에는 이상해 보일 수 있지만, 커링에 대해 이야기하고 나면 완벽히 말이 될 것이다. 여러 화살표가 있는 시그니처는 기본적으로 두 가지 방식으로 해석할 수 있다. 하나는 여러 인자를 받는 함수로, 가장 오른쪽 타입이 반환 타입이라고 보는 것이다. 다른 하나는 하나의 인자, 즉 가장 왼쪽 인자를 받아 함수를 반환하는 함수로 보는 것이다. 후자의 해석은 `m->(m->m)`처럼 괄호를 더해 강조할 수 있다. 화살표가 오른쪽 결합이므로 이 괄호는 중복이지만 말이다. 곧 이 해석으로 돌아오겠다.

하스켈에서는 `mempty`와 `mappend`의 모노이드 성질, 즉 `mempty`가 중립 원소이고 `mappend`가 결합적이라는 사실을 표현할 방법이 없다는 점에 주목하자. 이 성질들이 만족되도록 보장하는 것은 프로그래머의 책임이다.

하스켈 클래스는 C++ 클래스만큼 침투적이지 않다. 새 타입을 정의할 때 그 타입의 클래스를 미리 지정할 필요가 없다. 얼마든지 미루다가 훨씬 나중에 어떤 타입을 어떤 클래스의 인스턴스로 선언할 수 있다. 예를 들어 `mempty`와 `mappend`의 구현을 제공함으로써 `String`을 모노이드로 선언해 보자. 사실 표준 Prelude에서 이미 이렇게 해 준다.

```haskell
instance Monoid String where
    mempty = ""
    mappend = (++)
```

여기서는 리스트 연결 연산자 `(++)`를 재사용했다. `String`은 문자들의 리스트일 뿐이기 때문이다.

하스켈 문법에 대해 한마디 하자. 어떤 중위 연산자든 괄호로 감싸면 두 인자 함수로 바꿀 수 있다. 두 문자열이 주어졌을 때 그 사이에 `++`를 넣어 연결할 수 있다.

```haskell
"Hello " ++ "world!"
```

또는 괄호로 감싼 `(++)`에 두 인자를 넘길 수도 있다.

```haskell
(++) "Hello " "world!"
```

함수 인자들은 쉼표로 구분되지 않고 괄호로 둘러싸이지도 않는다는 점에 주목하자. 하스켈을 배울 때 아마 가장 익숙해지기 어려운 부분일 것이다.

하스켈이 다음처럼 함수의 동등성을 표현하게 해 준다는 점은 강조할 만하다.

```haskell
mappend = (++)
```

개념적으로 이것은 함수가 만들어 낸 값들의 동등성을 표현하는 다음 코드와 다르다.

```haskell
mappend s1 s2 = (++) s1 s2
```

앞의 식은 *Hask* 범주에서 사상의 동등성으로 번역된다. 끝나지 않는 계산을 뜻하는 bottom을 무시한다면 *Set*이라고 해도 된다. 이런 방정식은 더 간결할 뿐 아니라, 종종 다른 범주로 일반화될 수 있다. 뒤의 식은 외연적 동등성이라고 부르며, 임의의 두 입력 문자열에 대해 `mappend`와 `(++)`의 출력이 같다는 사실을 말한다. 인자의 값을 때때로 점이라고 부르므로, 예를 들어 점 x에서의 f의 값처럼 말이다, 이것을 점별 동등성이라고 부른다. 인자를 지정하지 않는 함수 동등성은 점 없는(point-free) 방식이라고 설명한다. 참고로 점 없는 방정식은 종종 함수 합성을 포함하는데, 함수 합성은 점으로 표기되므로 초보자에게는 약간 헷갈릴 수 있다.

C++에서 모노이드를 선언하는 데 가장 가까운 방법은 제안된 concepts 문법을 사용하는 것이다.

```cpp
template<class T>
  T mempty = delete;

template<class T>
  T mappend(T, T) = delete;

template<class M>
  concept bool Monoid = requires (M m) {
    { mempty<M> } -> M;
    { mappend(m, m); } -> M;
  };
```

첫 번째 정의는 값 템플릿, 역시 제안된 기능을 사용한다. 다형 값은 값들의 가족이다. 타입마다 다른 값이 하나씩 있다.

`delete` 키워드는 기본값이 정의되어 있지 않다는 뜻이다. 경우마다 따로 지정해야 한다. 마찬가지로 `mappend`에도 기본값은 없다.

`Monoid` concept는 주어진 타입 `M`에 대해 `mempty`와 `mappend`의 적절한 정의가 존재하는지 검사하는 술어다. 그래서 타입이 `bool`이다.

Monoid concept의 인스턴스화는 적절한 특수화와 오버로드를 제공함으로써 이룰 수 있다.

```cpp
template<>
std::string mempty<std::string> = {""};

std::string mappend(std::string s1, std::string s2) {
    return s1 + s2;
}
```

## 범주로서의 모노이드

지금까지는 집합의 원소들로 모노이드를 정의하는 "익숙한" 방식이었다. 하지만 알다시피 범주론에서는 집합과 그 원소에서 벗어나 객체와 사상에 대해 말하려고 한다. 그러니 관점을 조금 바꾸어, 이항 연산을 적용하는 일을 집합 안에서 무언가를 "이동"하거나 "옮기는" 일로 생각해 보자.

예를 들어 모든 자연수에 5를 더하는 연산이 있다. 이것은 0을 5로, 1을 6으로, 2를 7로 보내고, 계속 그렇게 한다. 자연수 집합 위에 정의된 함수다. 좋다. 우리에게는 함수와 집합이 있다. 일반적으로 임의의 수 n에 대해 n을 더하는 함수, 즉 n의 "adder"가 있다.

adder들은 어떻게 합성될까? 5를 더하는 함수와 7을 더하는 함수를 합성하면 12를 더하는 함수가 된다. 따라서 adder들의 합성은 덧셈의 규칙과 동등하게 만들 수 있다. 이것도 좋다. 덧셈을 함수 합성으로 바꿀 수 있다.

하지만 잠깐, 더 있다. 중립 원소인 0에 대한 adder도 있다. 0을 더하는 일은 아무것도 이동시키지 않으므로 자연수 집합의 항등 함수다.

전통적인 덧셈 규칙을 주는 대신 adder들의 합성 규칙을 주어도 정보 손실은 전혀 없다. adder들의 합성이 결합적인 이유는 함수 합성이 결합적이기 때문이다. 그리고 항등 함수에 대응하는 zero adder가 있다.

예리한 독자라면 정수에서 adder로 가는 대응이 `mappend`의 타입 시그니처를 `m->(m->m)`으로 해석하는 두 번째 방식에서 나온다는 것을 알아차렸을지도 모른다. 이 해석은 `mappend`가 모노이드 집합의 원소를 그 집합 위에서 작용하는 함수로 보낸다는 사실을 말해 준다.

이제 자연수 집합을 다루고 있다는 사실을 잊고, 그것을 하나의 객체, 그리고 그 위에 여러 사상인 adder들이 붙어 있는 덩어리로 생각해 보자. 모노이드는 단일 객체 범주다. 실제로 monoid라는 이름은 하나를 뜻하는 그리스어 mono에서 왔다. 모든 모노이드는 적절한 합성 규칙을 따르는 사상들의 집합을 가진 단일 객체 범주로 설명될 수 있다.

문자열 연결은 흥미로운 경우다. 오른쪽에 붙이는 함수와 왼쪽에 붙이는 함수, 원한다면 앞에 붙이는 함수, 중 어느 쪽으로 정의할지 선택할 수 있기 때문이다. 두 모델의 합성표는 서로 거울상이다. `"foo"` 뒤에 `"bar"`를 붙이는 것은 `"bar"`를 앞에 붙인 뒤 `"foo"`를 앞에 붙이는 것에 대응한다는 사실을 쉽게 확인할 수 있다.

모든 범주론적 모노이드, 즉 하나의 객체를 가진 범주가 유일한 이항 연산을 가진 집합 모노이드를 정의하는지 물을 수도 있다. 사실 단일 객체 범주에서는 언제나 집합을 추출할 수 있다. 이 집합은 사상들의 집합이다. 예제에서는 adder들의 집합이다. 다시 말해 범주 M의 단일 객체 m에 대한 hom-set M(m, m)을 얻는다. 이 집합에는 이항 연산을 쉽게 정의할 수 있다. 두 집합 원소의 모노이드 곱은 대응하는 사상들의 합성에 대응하는 원소다. `f`와 `g`에 대응하는 M(m, m)의 두 원소를 준다면, 그 곱은 합성 `g ∘ f`에 대응한다. 이 사상들의 시작과 대상이 같은 객체이므로 합성은 항상 존재한다. 그리고 범주의 규칙에 의해 결합적이다. 항등 사상은 이 곱의 중립 원소다. 따라서 우리는 언제나 범주 모노이드에서 집합 모노이드를 복원할 수 있다. 실질적으로 둘은 하나이며 같은 것이다.

![사상으로도, 집합의 점으로도 볼 수 있는 모노이드 hom-set](images/monoidhomset.jpg)

수학자들이 꼬투리를 잡을 만한 작은 점이 하나 있다. 사상들이 반드시 집합을 이루어야 하는 것은 아니다. 범주의 세계에는 집합보다 큰 것들이 있다. 임의의 두 객체 사이의 사상들이 집합을 이루는 범주를 국소적으로 작은 범주라고 부른다. 약속했듯이 나는 이런 미묘한 점을 대체로 무시하겠지만, 기록을 위해 언급해 두어야겠다고 생각했다.

범주론의 많은 흥미로운 현상은 hom-set의 원소들을 합성 규칙을 따르는 사상으로도 볼 수 있고, 집합의 점으로도 볼 수 있다는 사실에 뿌리를 둔다. 여기서 M 안의 사상 합성은 집합 M(m, m) 안의 모노이드 곱으로 번역된다.

## 감사의 말

내 C++ 모노이드 concept 코드를 Andrew Sutton과 Bjarne Stroustrup의 최신 제안에 맞게 다시 작성해 준 Andrew Sutton에게 감사드린다.
