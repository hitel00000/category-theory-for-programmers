# 곱과 쌍대곱

## 화살표를 따라가라

고대 그리스 극작가 에우리피데스는 이렇게 말했다. "사람은 자신이 늘 어울리는 무리와 닮는다." 우리는 관계로 정의된다. 범주론만큼 이 말이 잘 들어맞는 곳도 없다. 범주 안의 특정 객체를 골라내고 싶다면, 그 객체가 다른 객체들, 그리고 자기 자신과 맺는 관계의 패턴을 설명하는 수밖에 없다. 이런 관계는 사상으로 정의된다.

범주론에는 관계를 통해 객체를 정의하는 *보편 구성*이라는 흔한 구성이 있다. 이를 수행하는 한 가지 방법은 어떤 패턴, 즉 객체와 사상으로 만들어진 특정한 모양을 고르고, 그 범주 안에서 그 패턴이 나타나는 모든 경우를 찾는 것이다. 충분히 흔한 패턴이고 범주가 크다면, 아마 아주 많은 결과가 나올 것이다. 비결은 그 결과들 사이에 어떤 순위를 세우고, 가장 잘 맞는 것이라고 볼 수 있는 대상을 고르는 데 있다.

이 과정은 웹 검색을 하는 방식과 비슷하다. 질의는 패턴과 같다. 아주 일반적인 질의는 큰 *재현율*을 준다. 즉 결과가 많이 나온다. 그중 일부는 관련 있고, 일부는 관련 없을 수 있다. 관련 없는 결과를 제거하려면 질의를 다듬는다. 그러면 *정밀도*가 올라간다. 마지막으로 검색 엔진이 결과의 순위를 매기고, 바라건대 당신이 관심 있는 결과 하나가 목록 맨 위에 온다.

## 시작 객체

가장 단순한 모양은 객체 하나다. 분명 주어진 범주에 객체가 있는 만큼 이 모양의 인스턴스가 있다. 선택지가 너무 많다. 우리는 어떤 순위를 세우고 이 계층의 꼭대기에 있는 객체를 찾아야 한다. 우리가 쓸 수 있는 수단은 사상뿐이다. 사상을 화살표로 생각하면, 범주의 한쪽 끝에서 다른 쪽 끝으로 향하는 전체적인 화살표의 흐름이 있을 수 있다. 예를 들어 부분 순서 같은 순서 범주에서는 그렇다. 객체 *a*에서 객체 *b*로 가는 화살표, 즉 사상이 있으면 객체 *a*가 객체 *b*보다 "더 시작적"이라고 말함으로써 이런 객체 선행 관계를 일반화할 수 있다. 그러면 *그* 시작 객체를 다른 모든 객체로 가는 화살표를 가진 객체로 정의할 수 있을 것이다. 물론 그런 객체가 존재한다는 보장은 없고, 그래도 괜찮다. 더 큰 문제는 그런 객체가 너무 많을 수 있다는 것이다. 재현율은 좋지만 정밀도가 부족하다. 해결책은 순서 범주에서 힌트를 얻는 것이다. 순서 범주는 임의의 두 객체 사이에 많아야 하나의 화살표만 허용한다. 어떤 객체보다 작거나 같다는 방식은 하나뿐이다. 이것이 시작 객체의 다음 정의로 이어진다.

> **시작 객체**는 범주 안의 임의의 객체로 가는 사상이 정확히 하나 있는 객체다.

![](images/initial.jpg)

하지만 이것만으로도 시작 객체가 존재할 때 그 유일성이 보장되지는 않는다. 대신 그다음으로 좋은 것, 즉 *동형까지의 유일성*은 보장된다. 동형은 범주론에서 매우 중요하므로 곧 이야기하겠다. 지금은 동형까지의 유일성이 시작 객체의 정의에서 "그"라는 말을 쓰는 것을 정당화한다고 해 두자.

몇 가지 예를 보자. 부분 순서 집합, 흔히 *poset*이라고 부르는 것에서 시작 객체는 최소 원소다. 어떤 poset에는 시작 객체가 없다. 예를 들어 양수와 음수를 모두 포함한 모든 정수의 집합에 작거나 같음 관계를 사상으로 둔 경우가 그렇다.

집합과 함수의 범주에서 시작 객체는 공집합이다. 공집합은 하스켈 타입 `Void`에 대응한다는 것을 기억하자. C++에는 대응하는 타입이 없다. `Void`에서 임의의 다른 타입으로 가는 유일한 다형 함수는 `absurd`라고 부른다.

```haskell
absurd :: Void -> a
```

바로 이 사상들의 가족이 `Void`를 타입의 범주에서 시작 객체로 만든다.

## 끝 객체

객체 하나짜리 패턴을 계속 사용하되, 객체의 순위를 매기는 방식을 바꾸자. 객체 *b*에서 객체 *a*로 가는 사상이 있으면 객체 *a*가 객체 *b*보다 "더 끝적"이라고 말하겠다. 방향이 반대로 바뀐 점에 주목하자. 우리는 범주의 다른 어떤 객체보다 더 끝적인 객체를 찾을 것이다. 이번에도 유일성을 요구하겠다.

> **끝 객체**는 범주 안의 임의의 객체로부터 들어오는 사상이 정확히 하나 있는 객체다.

![](images/final.jpg)

다시 말하지만 끝 객체도 동형까지 유일하다. 곧 보이겠다. 하지만 먼저 몇 가지 예를 보자. poset에서 끝 객체가 존재한다면 그것은 가장 큰 객체다. 집합의 범주에서 끝 객체는 한 원소 집합이다. 우리는 이미 한 원소 집합에 대해 이야기했다. C++의 `void` 타입과 하스켈의 unit 타입 `()`에 대응한다. 이 타입은 값이 하나뿐이다. C++에서는 암시적이고, 하스켈에서는 `()`로 명시된다. 또한 임의의 타입에서 unit 타입으로 가는 순수 함수가 정확히 하나뿐이라는 것도 보았다.

```haskell
unit :: a -> ()
unit _ = ()
```

따라서 끝 객체의 모든 조건이 만족된다.

이 예에서 유일성 조건이 핵심이라는 점에 주목하자. 모든 집합으로부터 들어오는 사상을 가진 다른 집합들도 있기 때문이다. 사실 공집합을 제외한 모든 집합이 그렇다. 예를 들어 모든 타입에 대해 정의된 불리언 값 함수, 즉 술어가 있다.

```haskell
yes :: a -> Bool
yes _ = True
```

하지만 `Bool`은 끝 객체가 아니다. 모든 타입에서 `Bool`로 가는 함수가 적어도 하나 더 있다.

```haskell
no :: a -> Bool
no _ = False
```

유일성을 요구하면 끝 객체의 정의를 정확히 하나의 타입으로 좁히기에 알맞은 정밀도를 얻는다.

## 쌍대성

시작 객체와 끝 객체를 정의한 방식 사이의 대칭을 알아차리지 않을 수 없다. 둘의 유일한 차이는 사상의 방향이었다. 사실 임의의 범주 C에 대해 모든 화살표를 뒤집기만 하면 *반대 범주* C<sup>op</sup>를 정의할 수 있다. 합성을 동시에 다시 정의하기만 하면, 반대 범주는 자동으로 범주의 모든 요구 사항을 만족한다. 원래 사상 `f::a->b`와 `g::b->c`가 `h=g ∘ f`로 `h::a->c`에 합성된다면, 뒤집힌 사상 <pre>f<sup>op</sup>::b->a</pre>와 <pre>g<sup>op</sup>::c->b</pre>는 <pre>h<sup>op</sup>::c->a</pre>로 합성되고, 이때 <pre>h<sup>op</sup>=f<sup>op</sup> ∘ g<sup>op</sup></pre>이다. 항등 화살표를 뒤집는 것은, 말장난을 하자면, 아무 일도 하지 않는 no-op이다.

쌍대성은 범주의 매우 중요한 성질이다. 범주론을 하는 모든 수학자의 생산성을 두 배로 늘려 주기 때문이다. 어떤 구성을 하나 생각해 내면 그 반대가 있고, 어떤 정리를 하나 증명하면 하나를 공짜로 얻는다. 반대 범주의 구성에는 흔히 "co"라는 접두사가 붙는다. 그래서 product와 coproduct, monad와 comonad, cone과 cocone, limit과 colimit 등이 있다. 다만 cocomonad는 없다. 화살표를 두 번 뒤집으면 원래 상태로 돌아가기 때문이다.

따라서 끝 객체는 반대 범주의 시작 객체다.

## 동형

프로그래머인 우리는 동등성을 정의하는 일이 사소하지 않다는 것을 잘 알고 있다. 두 객체가 같다는 것은 무엇을 뜻하는가? 메모리의 같은 위치를 차지해야 하는가, 즉 포인터 동등성인가? 아니면 모든 구성 요소의 값이 같으면 충분한가? 하나는 실수부와 허수부로 표현되고 다른 하나는 크기와 각도로 표현된 두 복소수는 같은가? 수학자들은 동등성의 의미를 이미 정리했을 것이라고 생각할지도 모르지만, 그렇지 않다. 그들에게도 동등성에 대한 여러 경쟁적인 정의가 있다. 명제적 동등성, 내포적 동등성, 외연적 동등성, 그리고 호모토피 타입 이론에서의 경로로서의 동등성이 있다. 그리고 그보다 약한 동형의 개념, 더 약한 동치의 개념도 있다.

직관은 이렇다. 동형인 객체들은 똑같아 보인다. 같은 모양을 가진다. 한 객체의 모든 부분이 다른 객체의 어떤 부분과 일대일 대응한다는 뜻이다. 우리의 도구가 판별할 수 있는 한, 두 객체는 서로의 완벽한 복사본이다. 수학적으로는 객체 *a*에서 객체 *b*로 가는 사상이 있고, 객체 *b*에서 객체 *a*로 돌아오는 사상이 있으며, 이 둘이 서로의 역이라는 뜻이다. 범주론에서는 사상을 사용한다. 동형은 가역 사상, 또는 한쪽이 다른 한쪽의 역인 사상들의 쌍이다.

우리는 역을 합성과 항등의 관점에서 이해한다. 사상 *g*가 사상 *f*의 역이라는 말은 이들의 합성이 항등 사상이라는 뜻이다. 두 사상을 합성하는 방식이 두 가지 있으므로 실제로는 두 방정식이 있다.

```haskell
f . g = id
g . f = id
```

시작 객체나 끝 객체가 동형까지 유일하다고 말했을 때, 나는 임의의 두 시작 객체, 또는 끝 객체가 동형이라는 뜻으로 말했다. 이것은 사실 쉽게 볼 수 있다. 시작 객체 i<sub>1</sub>과 i<sub>2</sub>가 두 개 있다고 하자. i<sub>1</sub>이 시작 객체이므로 i<sub>1</sub>에서 i<sub>2</sub>로 가는 유일한 사상 *f*가 있다. 같은 이유로 i<sub>2</sub>가 시작 객체이므로 i<sub>2</sub>에서 i<sub>1</sub>로 가는 유일한 사상 *g*가 있다. 이 두 사상의 합성은 무엇인가?

![이 그림의 모든 사상은 유일하다](images/uniqueness.jpg)

합성 *g ∘ f*는 i<sub>1</sub>에서 i<sub>1</sub>로 가는 사상이어야 한다. 하지만 i<sub>1</sub>은 시작 객체이므로 i<sub>1</sub>에서 i<sub>1</sub>로 가는 사상은 하나뿐일 수 있다. 우리는 범주 안에 있으므로 i<sub>1</sub>에서 i<sub>1</sub>로 가는 항등 사상이 있다는 것을 알고, 들어갈 자리가 하나뿐이므로 그것이 바로 그 사상이어야 한다. 따라서 *g ∘ f*는 항등과 같다. 마찬가지로 *f ∘ g*도 항등과 같아야 한다. i<sub>2</sub>에서 다시 i<sub>2</sub>로 가는 사상도 하나뿐이기 때문이다. 이것은 *f*와 *g*가 서로의 역이어야 함을 증명한다. 따라서 임의의 두 시작 객체는 동형이다.

이 증명에서 시작 객체에서 자기 자신으로 가는 사상의 유일성을 사용했다는 점에 주목하자. 그것이 없었다면 "동형까지"라는 부분을 증명할 수 없었을 것이다. 그렇다면 왜 *f*와 *g*의 유일성이 필요한가? 시작 객체는 동형까지 유일할 뿐 아니라 *유일한* 동형까지 유일하기 때문이다. 원칙적으로 두 객체 사이에는 동형이 둘 이상 있을 수 있지만, 여기서는 그렇지 않다. 이 "유일한 동형까지의 유일성"은 모든 보편 구성의 중요한 성질이다.

## 곱

다음 보편 구성은 곱이다. 두 집합의 데카르트 곱이 무엇인지는 안다. 그것은 쌍들의 집합이다. 하지만 곱 집합과 그 구성 집합들을 연결하는 패턴은 무엇일까? 그것을 알아내면 다른 범주로 일반화할 수 있다.

우리가 말할 수 있는 것은 곱에서 각 구성 요소로 가는 두 함수, 즉 사영이 있다는 것뿐이다. 하스켈에서 이 두 함수는 `fst`와 `snd`라고 부르며, 각각 쌍의 첫 번째와 두 번째 구성 요소를 고른다.

```haskell
fst :: (a, b) -> a
fst (x, y) = x
```

```haskell
snd :: (a, b) -> b
snd (x, y) = y
```

여기서 함수들은 인자를 패턴 매칭해 정의된다. 임의의 쌍과 맞는 패턴은 `(x, y)`이고, 그 구성 요소들을 변수 `x`와 `y`로 추출한다.

와일드카드를 사용하면 이 정의는 더 단순해질 수 있다.

```haskell
fst (x, _) = x
snd (_, y) = y
```

C++에서는 예를 들어 다음처럼 템플릿 함수를 사용할 것이다.

```cpp
template<class A, class B>
A fst(pair<A, B> const & p) {
    return p.first;
}
```

이처럼 겉보기에는 매우 제한적인 지식만 가지고, 집합의 범주에서 두 집합 *a*와 *b*의 곱 구성으로 이어질 객체와 사상의 패턴을 정의해 보자. 이 패턴은 객체 *c*와, 그것을 각각 *a*와 *b*에 연결하는 두 사상 *p*와 *q*로 이루어진다.

```haskell
p :: c -> a
q :: c -> b
```

![](images/productpattern.jpg)

이 패턴에 맞는 모든 *c*는 곱의 후보로 간주된다. 그런 후보는 많을 수 있다.

![](images/productcandidates.jpg)

예를 들어 구성 요소로 하스켈 타입 `Int`와 `Bool`을 고르고, 그 곱의 후보 몇 가지를 살펴보자.

첫 번째 후보는 `Int`다. `Int`를 `Int`와 `Bool`의 곱 후보로 볼 수 있을까? 그렇다. 다음과 같은 사영들이 있기 때문이다.

```haskell
p :: Int -> Int
p x = x

q :: Int -> Bool
q _ = True
```

꽤 볼품없지만 기준에는 맞는다.

또 다른 후보는 `(Int, Int, Bool)`이다. 세 원소의 튜플, 즉 triple이다. 이것을 정당한 후보로 만드는 두 사상은 다음과 같다. 여기서는 triple에 대한 패턴 매칭을 사용한다.

```haskell
p :: (Int, Int, Bool) -> Int
p (x, _, _) = x

q :: (Int, Int, Bool) -> Bool
q (_, _, b) = b
```

첫 번째 후보는 너무 작았다. 곱의 `Int` 차원만 덮었다. 두 번째 후보는 너무 컸다. `Int` 차원을 불필요하게 복제했다.

하지만 우리는 아직 보편 구성의 다른 부분, 즉 순위를 탐구하지 않았다. 우리는 패턴의 두 인스턴스를 비교할 수 있기를 원한다. 후보 객체 *c*와 그 두 사영 *p*, *q*를 다른 후보 객체 *c'*와 그 두 사영 *p'*, *q'*와 비교하고 싶다. *c'*에서 *c*로 가는 사상 *m*이 있으면 *c*가 *c'*보다 "더 좋다"고 말하고 싶을 수도 있다. 하지만 그것만으로는 너무 약하다. 우리는 그 사영들도 *c'*의 사영들보다 "더 좋다", 또는 "더 보편적이다"라고 말하고 싶다. 이는 *p'*와 *q'*를 *m*을 사용해 *p*와 *q*로부터 재구성할 수 있다는 뜻이다.

```haskell
p' = p . m
q' = q . m
```

![](images/productranking.jpg)

이 방정식을 보는 또 다른 방식은 *m*이 *p'*와 *q'*를 *인수분해*한다고 말하는 것이다. 이 방정식들이 자연수에 관한 식이고 점이 곱셈이라고 상상해 보라. *m*은 *p'*와 *q'*가 공유하는 공통 인수다.

직관을 조금 만들기 위해, 표준 사영 `fst`와 `snd`를 가진 쌍 `(Int, Bool)`이 앞서 제시한 두 후보보다 실제로 더 낫다는 것을 보여 주겠다.

![](images/not-a-product.jpg)

첫 번째 후보에 대한 사상 `m`은 다음과 같다.

```haskell
m :: Int -> (Int, Bool)
m x = (x, True)
```

실제로 두 사영 `p`와 `q`는 다음처럼 재구성된다.

```haskell
p x = fst (m x) = x
q x = snd (m x) = True
```

두 번째 예에 대한 `m`도 마찬가지로 유일하게 결정된다.

```haskell
m (x, _, b) = (x, b)
```

우리는 `(Int, Bool)`이 두 후보 중 어느 것보다도 낫다는 것을 보일 수 있었다. 반대가 왜 참이 아닌지 보자. `p`와 `q`로부터 `fst`와 `snd`를 재구성하도록 도와주는 어떤 `m'`을 찾을 수 있을까?

```haskell
fst = p . m'
snd = q . m'
```

첫 번째 예에서 `q`는 항상 `True`를 반환했고, 두 번째 구성 요소가 `False`인 쌍들이 있다는 것을 우리는 안다. `q`로부터 `snd`를 재구성할 수 없다.

두 번째 예는 다르다. `p`나 `q`를 실행한 뒤에도 충분한 정보는 남아 있지만, `fst`와 `snd`를 인수분해하는 방법이 하나보다 많다. `p`와 `q`가 모두 triple의 두 번째 구성 요소를 무시하므로, 우리의 `m'`은 그 자리에 아무것이나 넣을 수 있다. 예를 들어 다음이 가능하다.

```haskell
m'(x, b) = (x, x, b)
```

또는 다음도 가능하다.

```haskell
m'(x, b) = (x, 42, b)
```

이런 식이다.

모두 합치면, 두 사영 `p`와 `q`를 가진 임의의 타입 `c`가 주어졌을 때, 그것들을 인수분해하는 `c`에서 데카르트 곱 `(a, b)`로 가는 유일한 `m`이 있다. 사실 그것은 `p`와 `q`를 쌍으로 결합할 뿐이다.

```haskell
m :: c -> (a, b)
m x = (p x, q x)
```

이로써 데카르트 곱 `(a, b)`가 우리의 최적 일치가 된다. 이는 이 보편 구성이 집합의 범주에서 작동한다는 뜻이다. 이 구성은 임의의 두 집합의 곱을 골라낸다.

이제 집합을 잊고, 같은 보편 구성을 사용해 임의의 범주에서 두 객체의 곱을 정의하자. 그런 곱은 항상 존재하지는 않지만, 존재한다면 유일한 동형까지 유일하다.

> 두 객체 *a*와 *b*의 **곱**은 두 사영을 갖춘 객체 *c*로서, 두 사영을 갖춘 임의의 다른 객체 *c'*에 대해 그 사영들을 인수분해하는 *c'*에서 *c*로 가는 유일한 사상 *m*이 존재하는 객체다.

두 후보로부터 인수분해 함수 `m`을 만들어 내는 고차 함수를 때때로 *factorizer*라고 부른다. 우리의 경우에는 다음 함수가 될 것이다.

```haskell
factorizer :: (c -> a) -> (c -> b) -> (c -> (a, b))
factorizer p q = \x -> (p x, q x)
```

## 쌍대곱

범주론의 모든 구성처럼 곱에도 쌍대가 있고, 그것을 쌍대곱이라고 부른다. 곱 패턴에서 화살표를 뒤집으면, 두 *주입* `i`와 `j`를 갖춘 객체 *c*를 얻게 된다. 여기서 주입은 *a*와 *b*에서 *c*로 가는 사상이다.

```haskell
i :: a -> c
j :: b -> c
```

![](images/coproductpattern.jpg)

순위도 뒤집힌다. 주입 *i'*와 *j'*를 갖춘 객체 *c'*에 대해, 주입들을 인수분해하는 *c*에서 *c'*로 가는 사상 *m*이 있으면 객체 *c*가 객체 *c'*보다 "더 좋다"고 한다.

```haskell
i' = m . i
j' = m . j
```

![](images/coproductranking.jpg)

그런 객체들 중 "최고"인 것, 즉 임의의 다른 패턴으로 가는 유일한 사상을 가진 객체를 쌍대곱이라고 부르며, 존재한다면 유일한 동형까지 유일하다.

> 두 객체 *a*와 *b*의 **쌍대곱**은 두 주입을 갖춘 객체 *c*로서, 두 주입을 갖춘 임의의 다른 객체 *c'*에 대해 그 주입들을 인수분해하는 *c*에서 *c'*로 가는 유일한 사상 *m*이 존재하는 객체다.

집합의 범주에서 쌍대곱은 두 집합의 *서로소 합집합*이다. *a*와 *b*의 서로소 합집합의 원소는 *a*의 원소이거나 *b*의 원소다. 두 집합이 겹친다면, 서로소 합집합에는 공통 부분의 복사본이 두 개 들어간다. 서로소 합집합의 원소는 그 출처를 나타내는 식별자가 붙은 값이라고 생각할 수 있다.

프로그래머에게는 타입의 관점에서 쌍대곱을 이해하는 편이 더 쉽다. 그것은 두 타입의 태그 달린 유니언이다. C++는 유니언을 지원하지만 태그가 붙어 있지 않다. 즉 프로그램 안에서 유니언의 어떤 멤버가 유효한지 어떻게든 추적해야 한다. 태그 달린 유니언을 만들려면 태그, 즉 열거형을 정의하고 그것을 유니언과 결합해야 한다. 예를 들어 `int`와 `char const *`의 태그 달린 유니언은 다음처럼 구현할 수 있다.

```cpp
struct Contact {
    enum { isPhone, isEmail } tag;
    union { int phoneNum; char const * emailAddr; };
};
```

두 주입은 생성자로 구현할 수도 있고 함수로 구현할 수도 있다. 예를 들어 첫 번째 주입을 함수 `PhoneNum`으로 쓰면 다음과 같다.

```cpp
Contact PhoneNum(int n) {
    Contact c;
    c.tag = isPhone;
    c.phoneNum = n;
    return c;
}
```

이 함수는 정수를 `Contact` 안으로 주입한다.

태그 달린 유니언은 *variant*라고도 부르며, boost 라이브러리에는 매우 일반적인 variant 구현인 `boost::variant`가 있다.

하스켈에서는 데이터 생성자들을 세로 막대로 구분해 임의의 데이터 타입들을 태그 달린 유니언으로 결합할 수 있다. `Contact` 예제는 다음 선언으로 번역된다.

```haskell
data Contact = PhoneNum Int | EmailAddr String
```

여기서 `PhoneNum`과 `EmailAddr`는 생성자, 즉 주입으로도 쓰이고, 패턴 매칭을 위한 태그로도 쓰인다. 이에 대해서는 나중에 더 이야기하겠다. 예를 들어 전화번호를 사용해 연락처를 만드는 방법은 다음과 같다.

```haskell
helpdesk :: Contact;
helpdesk = PhoneNum 2222222
```

곱의 표준 구현이 하스켈에 기본 쌍으로 내장되어 있는 것과 달리, 쌍대곱의 표준 구현은 `Either`라는 데이터 타입이다. 표준 Prelude에는 다음처럼 정의되어 있다.

```haskell
Either a b = Left a | Right b
```

이 타입은 두 타입 `a`와 `b`로 매개변수화되며, 두 생성자를 가진다. `Left`는 타입 `a`의 값을 받고, `Right`는 타입 `b`의 값을 받는다.

곱에 대한 factorizer를 정의했듯이, 쌍대곱에 대해서도 하나를 정의할 수 있다. 후보 타입 `c`와 두 후보 주입 `i`, `j`가 주어졌을 때, `Either`에 대한 factorizer는 인수분해 함수를 만들어 낸다.

```haskell
factorizer :: (a -> c) -> (b -> c) -> Either a b -> c
factorizer i j (Left a)  = i a
factorizer i j (Right b) = j b
```

## 비대칭성

우리는 두 쌍의 쌍대 정의를 보았다. 끝 객체의 정의는 시작 객체의 정의에서 화살표 방향을 뒤집어 얻을 수 있다. 비슷하게 쌍대곱의 정의는 곱의 정의에서 얻을 수 있다. 그러나 집합의 범주에서 시작 객체는 끝 객체와 매우 다르고, 쌍대곱은 곱과 매우 다르다. 나중에 곱은 곱셈처럼 행동하고 끝 객체가 1의 역할을 한다는 것을 보게 될 것이다. 반면 쌍대곱은 합에 더 가깝게 행동하고 시작 객체가 0의 역할을 한다. 특히 유한 집합의 경우 곱의 크기는 개별 집합 크기의 곱이고, 쌍대곱의 크기는 크기들의 합이다.

이는 집합의 범주가 화살표를 뒤집는 것에 대해 대칭적이지 않다는 것을 보여 준다.

공집합은 임의의 집합으로 가는 유일한 사상, 즉 `absurd` 함수를 갖지만, 되돌아오는 사상은 없다는 점에 주목하자. 한 원소 집합은 임의의 집합으로부터 들어오는 유일한 사상을 갖지만, 동시에 모든 집합으로 나가는 사상도 갖는다. 공집합은 제외한다. 앞서 보았듯이 끝 객체에서 나가는 이 사상들은 다른 집합의 원소를 고르는 매우 중요한 역할을 한다. 공집합에는 원소가 없으므로 고를 것이 없다.

한 원소 집합을 쌍대곱과 구별되게 만드는 것은 그것이 곱과 맺는 관계다. unit 타입 `()`로 표현되는 한 원소 집합을 곱 패턴의 또 다른, 매우 열등한 후보로 사용한다고 생각해 보자. 이 후보에 두 사영 `p`와 `q`, 즉 한 원소 집합에서 각 구성 집합으로 가는 함수를 붙인다. 각각은 해당 집합에서 구체적인 원소 하나를 고른다. 곱은 보편적이므로, 우리의 후보인 한 원소 집합에서 곱으로 가는 유일한 사상 `m`도 있다. 이 사상은 곱 집합에서 원소 하나, 즉 구체적인 쌍 하나를 고른다. 또한 이 사상은 두 사영을 인수분해한다.

```haskell
p = fst . m
q = snd . m
```

한 원소 집합의 유일한 원소인 unit 값 `()`에 작용할 때, 이 두 방정식은 다음이 된다.

```haskell
p () = fst (m ())
q () = snd (m ())
```

`m ()`은 `m`이 고른 곱의 원소이므로, 이 방정식들은 `p`가 첫 번째 집합에서 고른 원소 `p ()`가 `m`이 고른 쌍의 첫 번째 구성 요소라는 것을 말해 준다. 마찬가지로 `q ()`는 두 번째 구성 요소와 같다. 이는 곱의 원소가 구성 집합들의 원소로 이루어진 쌍이라는 우리의 이해와 완전히 일치한다.

쌍대곱에는 이런 단순한 해석이 없다. 쌍대곱에서 원소를 추출하려는 시도로 한 원소 집합을 후보로 삼아 볼 수는 있지만, 그 경우에는 밖으로 나오는 두 사영이 아니라 그 안으로 들어가는 두 주입이 있을 뿐이다. 이들은 원천에 대해 아무것도 말해 주지 않는다. 사실 앞서 보았듯이 입력 매개변수를 무시한다. 쌍대곱에서 우리의 한 원소 집합으로 가는 유일한 사상도 마찬가지다. 집합의 범주는 시작 객체 쪽에서 볼 때와 끝 객체 쪽에서 볼 때 매우 다르게 보인다.

이것은 집합의 고유한 성질이 아니라 **Set**에서 사상으로 사용하는 함수의 성질이다. 함수는 일반적으로 비대칭적이다. 설명해 보겠다.

함수는 정의역 집합의 모든 원소에 대해 정의되어야 한다. 프로그래밍에서는 이를 *전* 함수라고 부른다. 하지만 공역 전체를 덮을 필요는 없다. 우리는 그 극단적인 경우를 보았다. 한 원소 집합에서 출발하는 함수, 즉 공역에서 원소 하나만 선택하는 함수다. 사실 공집합에서 출발하는 함수가 진짜 극단이다. 정의역의 크기가 공역의 크기보다 훨씬 작을 때, 우리는 종종 그런 함수를 정의역을 공역 안에 묻어 넣는 것으로 생각한다. 예를 들어 한 원소 집합에서 출발하는 함수는 그 하나의 원소를 공역 안에 묻어 넣는 것으로 생각할 수 있다. 나는 이를 *embedding* 함수라고 부르지만, 수학자들은 그 반대쪽에 이름을 붙이기를 더 좋아한다. 공역을 빽빽하게 채우는 함수를 *전사* 또는 *onto*라고 부른다.

비대칭성의 또 다른 원천은 함수가 정의역 집합의 여러 원소를 공역의 한 원소로 보낼 수 있다는 점이다. 함수는 원소들을 붕괴시킬 수 있다. 극단적인 경우는 전체 집합을 한 원소 집합으로 보내는 함수다. 우리는 바로 그런 일을 하는 다형 함수 `unit`을 보았다. 붕괴는 합성에 의해 더해질 수밖에 없다. 두 붕괴 함수의 합성은 개별 함수보다 더 많이 붕괴한다. 수학자들은 붕괴하지 않는 함수에 이름을 붙였다. 그런 함수를 *단사* 또는 *일대일*이라고 부른다.

물론 embedding도 아니고 collapsing도 아닌 함수들이 있다. 이들은 *전단사*라고 부르며, 가역적이기 때문에 진정으로 대칭적이다. 집합의 범주에서 동형은 전단사와 같다.

5. 두 주입을 갖춘 `int`보다 `Either`가 "더 나은" 쌍대곱임을 보여라.

    ```cpp
int i(int n) { return n; }
    int j(bool b) { return b? 0: 1; }
```

    힌트: 다음 함수를 정의하라.

    ```cpp
int m(Either const & e);
```

    이 함수가 `i`와 `j`를 인수분해하게 하라.

6. 앞 문제를 계속하자. 두 주입 `i`와 `j`를 갖춘 `int`가 `Either`보다 "더 나을" 수 없다는 것을 어떻게 주장하겠는가?

7. 계속해서, 다음 주입들은 어떤가?

    ```cpp
int i(int n) { 
        if (n < 0) return n; 
        return n + 2;
    }
    int j(bool b) { return b? 0: 1; }
```

8. `int`와 `bool`의 쌍대곱에 대한 열등한 후보를 하나 제시하라. 그 후보에서 `Either`로 가는 허용 가능한 사상이 여러 개 생기기 때문에 `Either`보다 나을 수 없어야 한다.
