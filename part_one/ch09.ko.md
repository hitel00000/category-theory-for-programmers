# 함수 타입 {#function-types}

지금까지 함수 타입의 의미를 대충 넘어갔다. 함수 타입은 다른 타입과 다르다.

예를 들어 `Integer`는 정수의 집합일 뿐이다. `Bool`은 원소가 두 개인 집합이다. 하지만 함수 타입 `a->b`는 그 이상이다. 객체 `a`와 `b` 사이 사상들의 집합이다. 임의의 범주에서 두 객체 사이 사상의 집합을 hom-set이라고 한다. **Set** 범주에서는 모든 hom-set 자체가 같은 범주의 객체이기도 하다. 결국 그것 역시 *집합*이기 때문이다.

![Set의 Hom-set은 그저 집합이다](images/set-hom-set.jpg)


다른 범주에서는 그렇지 않다. hom-set은 범주 외부에 있으며, 실제로 *외부* hom-set이라고 부른다.

![범주 C의 Hom-set은 외부 집합이다](images/hom-set.jpg)

함수 타입이 특별한 이유는 **Set** 범주의 자기 참조적 성질에 있다. 하지만 적어도 몇몇 범주에서는 hom-set을 나타내는 객체를 구성할 방법이 있다. 이런 객체를 *내부* hom-set이라고 한다.

## 보편적 구성

함수 타입이 집합이라는 사실은 잠시 잊고, 함수 타입 또는 더 일반적으로 내부 hom-set을 처음부터 구성해 보자. 늘 그렇듯 **Set** 범주에서 실마리를 얻되 집합의 어떤 성질도 사용하지 않도록 조심할 것이다. 그러면 이 구성은 다른 범주에서도 자동으로 작동한다.

함수 타입은 인자 타입 및 결과 타입과 관계를 맺으므로 복합 타입으로 볼 수 있다. 객체 사이의 관계를 포함하는 복합 타입의 구성은 이미 보았다. [곱 타입과 쌍대곱 타입](#products-and-coproducts)을 정의할 때 보편적 구성을 사용했다. 같은 기법으로 함수 타입도 정의할 수 있다. 여기에는 우리가 구성하는 함수 타입, 인자 타입, 결과 타입이라는 세 객체가 얽힌 패턴이 필요하다.

이 세 타입을 잇는 명백한 패턴을 *함수 적용* 또는 *평가*라고 한다. 함수 타입의 후보를 `z`라고 하고, 인자 타입을 `a`라고 하자. **Set** 범주에 있지 않다면 `z`도 다른 객체와 다를 바 없는 객체일 뿐이라는 점에 주목하자. 적용은 이 쌍을 결과 타입 `b`로 보낸다. 객체가 셋이고 그중 인자 타입과 결과 타입을 나타내는 둘은 고정되어 있다.

사상인 적용도 있다. 이 사상을 패턴에 어떻게 넣을까? 객체 내부를 들여다볼 수 있다면 함수 `f`, 즉 `z`의 원소와 인자 `x`, 즉 `a`의 원소를 짝지어 `f x`, 즉 `f`를 `x`에 적용한 `b`의 원소로 보낼 수 있다.

![Set에서는 함수의 집합 z에서 함수 f를, 집합 또는 타입 a에서 인자 x를 고를 수 있다. 그러면 집합 또는 타입 b의 원소 f x를 얻는다.](images/functionset.jpg)

하지만 개별 쌍 `(f, x)`을 다루는 대신 함수 타입 `z`와 인자 타입 `a`의 *곱* 전체를 이야기해도 된다. 곱 `z×a`는 객체이며, 이 객체에서 `b`로 가는 화살표 `g`를 적용 사상으로 고를 수 있다. **Set**에서 `g`는 모든 쌍 `(f, x)`을 `f x`로 보내는 함수다.

따라서 패턴은 이렇다. 객체 `z`와 `a`의 곱이 사상 `g`로 다른 객체 `b`에 연결되어 있다.

![보편적 구성의 출발점인 객체와 사상의 패턴](images/functionpattern.jpg)

이 패턴은 보편적 구성으로 함수 타입 하나를 골라낼 만큼 구체적일까? 모든 범주에서 그런 것은 아니지만 우리가 관심을 두는 범주에서는 그렇다. 또 다른 질문도 있다. 곱을 먼저 정의하지 않고 함수 객체를 정의할 수 있을까? 곱이 없거나 모든 객체 쌍에 대해 곱이 존재하지 않는 범주도 있다. 답은 아니다. 곱 타입이 없으면 함수 타입도 없다. 지수에 대해 이야기할 때 다시 돌아오겠다.

보편적 구성을 복습해 보자. 객체와 사상의 패턴으로 시작한다. 이것은 부정확한 질의이므로 보통 수많은 결과를 내놓는다. 특히 **Set**에서는 거의 모든 것이 모든 것과 연결되어 있다. 임의의 객체 `z`를 가져와 `a`와 곱을 만들면 거기서 `b`로 가는 함수가 있을 것이다. 단, `b`가 공집합인 경우는 제외한다.

그때 비밀 병기인 순위 매기기를 적용한다. 보통 후보 객체 사이에 우리 구성을 어떤 식으로든 인수분해하는 유일한 사상이 존재하도록 요구한다. 이 경우 `z×a`에서 `b`로 가는 사상 `g`를 갖춘 `z`가 자체 적용 `g'`을 갖춘 다른 `z'`보다 *더 낫다*고 정하자. 그 조건은 `z'`에서 `z`로 가는 유일한 사상 `h`가 존재해 `g'`의 적용이 `g`의 적용을 거쳐 인수분해되는 것이다. 힌트: 그림을 보면서 이 문장을 읽어라.

![함수 객체 후보 사이의 순위 설정](images/functionranking.jpg)

이제 까다로운 부분이 나온다. 이 보편적 구성을 지금까지 미룬 주된 이유이기도 하다. 사상 `h :: z'-> z`가 주어졌을 때 `z'`과 `z` 각각에 `a`를 곱한 도형을 닫고 싶다. 실제로 필요한 것은 `z'`에서 `z`로 가는 사상 `h`가 주어졌을 때 `z'×a`에서 `z×a`로 가는 사상이다. 이제 [곱의 functoriality](#functoriality)를 논의했으므로 그 방법을 안다. 곱 자체가 functor, 더 정확히는 endo-bifunctor이므로 사상 쌍을 끌어올릴 수 있다. 다시 말해 객체의 곱뿐 아니라 사상의 곱도 정의할 수 있다.

곱 `z'×a`의 두 번째 성분은 건드리지 않으므로 사상 쌍 `(h, id)`를 끌어올린다. 여기서 `id`는 `a`의 항등이다.

따라서 한 적용 `g'`에서 다른 적용 `g`를 다음처럼 인수분해할 수 있다.

```haskell
g' = g ∘ (h × id)
```

핵심은 곱이 사상에 작용하는 방식이다.

보편적 구성의 세 번째 단계는 보편적으로 가장 좋은 객체를 고르는 것이다. 이 객체를 `a⇒b`라고 부르자. 이는 한 객체의 상징적 이름이며 하스켈 타입 클래스 제약과 혼동해서는 안 된다. 다른 이름 표기법은 나중에 설명하겠다. 이 객체는 `(a⇒b)×a`에서 `b`로 가는 자체 적용 사상을 가지며, 이를 `eval`이라고 하겠다. 다른 모든 함수 객체 후보가 적용 사상 `g`를 `eval`을 거쳐 인수분해하는 방식으로 `a⇒b`에 유일하게 보내질 수 있다면 객체 `a⇒b`가 가장 좋다. 우리의 순위에 따르면 다른 어떤 객체보다도 낫다.

![보편적 함수 객체의 정의. 위와 같은 도형이지만 이제 객체 `a⇒b`가 보편적이다.](images/universalfunctionobject.jpg)

형식적으로는 다음과 같다.

<table>

<tr>

<td>`a`에서 `b`로 가는 **함수 객체**는 다음 사상을 갖춘 객체 `a⇒b`다.

```
eval :: ((a⇒b) × a) -> b
```

다음 사상을 갖춘 다른 모든 객체 `z`에 대해

```
g :: z × a -> b
```

`g`를 `eval`을 거쳐 인수분해하는 유일한 사상

```

```

가 존재한다.

```
g = eval ∘ (h × id)
```

</td>

</tr>

물론 주어진 범주의 모든 객체 쌍 `a`와 `b`에 대해 그런 객체 `a⇒b`가 존재한다는 보장은 없다. 하지만 **Set**에서는 언제나 존재한다. 더 나아가 **Set**에서 이 객체는 hom-set *Set(a, b)*와 동형이다.

그래서 하스켈에서는 함수 타입 `a->b`를 범주론적 함수 객체 `a⇒b`로 해석한다.

## 커링

함수 객체의 모든 후보를 다시 살펴보자. 다만 이번에는 사상 `g`를 두 변수 `z`와 `a`의 함수로 생각해 보자.

```haskell
g :: z × a -> b
```

곱에서 출발하는 사상은 두 변수의 함수에 최대한 가까운 것이다. 특히 **Set**에서 `g`는 집합 `z`와 집합 `a`에서 하나씩 가져온 값의 쌍을 받는 함수다.

한편 보편적 속성에 따르면 각각의 `g`에 대해 `z`를 함수 객체 `a⇒b`로 보내는 유일한 사상 `h`가 있다.

```haskell
h :: z -> (a⇒b)
```

**Set**에서 이는 `h`가 `z` 타입의 변수 하나를 받아 `a`에서 `b`로 가는 함수를 반환하는 함수라는 뜻일 뿐이다. 따라서 `h`는 고차 함수다. 그러므로 보편적 구성은 두 변수의 함수와 함수를 반환하는 한 변수의 함수 사이에 일대일 대응을 세운다. 이 대응을 *커링*이라고 하며 `h`를 `g`의 커링된 버전이라고 한다.

이 대응은 일대일이다. 임의의 `g`에 대해 유일한 `h`가 있고, 임의의 `h`가 주어지면 다음 공식으로 두 인자 함수 `g`를 언제나 다시 만들 수 있기 때문이다.

```haskell
g = eval ∘ (h × id)
```

함수 `g`는 `h`의 *커링되지 않은* 버전이라고 할 수 있다.

커링은 사실상 하스켈 문법에 내장되어 있다. 함수를 반환하는 함수:

```haskell
a -> (b -> c)
```

를 흔히 두 변수의 함수로 생각한다. 괄호가 없는 다음 시그니처도 그렇게 읽는다.

```haskell
a -> b -> c
```

이 해석은 여러 인자를 받는 함수를 정의하는 방식에 드러난다. 예를 들면 다음과 같다.

```haskell
catstr :: String -> String -> String
catstr s s’ = s ++ s’
```

같은 함수를 함수를 반환하는 한 인자 함수, 즉 람다로 쓸 수 있다.

```haskell
catstr’ s = \s’ -> s ++ s’
```

두 정의는 동등하며 어느 쪽이든 인자 하나에만 부분 적용해 다음처럼 한 인자 함수를 만들 수 있다.

```haskell
greet :: String -> String
greet = catstr “Hello “
```

엄밀히 말해 두 변수의 함수는 쌍, 즉 곱 타입을 받는 함수다.

```haskell
(a, b) -> c
```

두 표현 사이의 변환은 간단하며, 이를 수행하는 두 고차 함수에는 당연하게도 `curry`와 `uncurry`라는 이름이 붙었다.

```haskell
curry :: ((a, b)->c) -> (a->b->c)
curry f a b = f (a, b)
```

그리고:

```haskell
uncurry :: (a->b->c) -> ((a, b)->c)
uncurry f (a, b) = f a b
```

`curry`가 함수 객체의 보편적 구성을 위한 *인수분해자*라는 점에 주목하자. 다음 형태로 다시 쓰면 특히 분명하다.

```haskell
factorizer :: ((a, b)->c) -> (a->(b->c))
factorizer g = \a -> (\b -> g (a, b))
```

상기하자면 인수분해자는 후보에서 인수분해하는 함수를 만들어 낸다.

C++ 같은 비함수형 언어에서도 커링은 가능하지만 간단하지 않다. C++의 여러 인자 함수는 튜플을 받는 하스켈 함수에 대응한다고 생각할 수 있다. 더 혼란스럽게도 C++에서는 명시적인 `std::tuple`을 받는 함수뿐 아니라 가변 인자 함수와 초기화 목록을 받는 함수도 정의할 수 있다.

`std::bind` 템플릿을 사용해 C++ 함수를 부분 적용할 수 있다. 예를 들어 문자열 두 개를 받는 함수가 있다고 하자.

```cpp
std::string catstr(std::string s1, std::string s2) {
    return s1 + s2;
}
```

문자열 하나를 받는 함수를 정의할 수 있다.

```cpp
using namespace std::placeholders;

auto greet = std::bind(catstr, "Hello ", _1);
std::cout << greet("Haskell Curry");
```

C++나 Java보다 함수형인 Scala는 그 중간쯤에 있다. 정의하는 함수를 부분 적용할 것이라고 예상한다면 여러 인자 목록을 사용해 정의한다.

```
def catstr(s1: String)(s2: String) = s1 + s2
```

물론 라이브러리 작성자에게 어느 정도의 선견지명이나 예지력이 필요하다.

## 지수

수학 문헌에서는 함수 객체 또는 두 객체 `a`와 `b` 사이의 내부 hom-객체를 흔히 *지수*라고 부르며 b<sup>a</sup>로 표기한다. 인자 타입이 지수에 들어간다는 점에 주목하자. 처음에는 이 표기가 이상해 보일 수 있지만, 함수와 곱의 관계를 생각하면 완벽하게 이해된다. 내부 hom-객체의 보편적 구성에 곱을 사용해야 한다는 것은 이미 보았지만, 둘 사이의 연결은 그보다 더 깊다.

`Bool`, `Char`, 심지어 `Int`나 `Double`처럼 값의 개수가 유한한 타입 사이의 함수를 생각하면 이를 가장 잘 볼 수 있다. 이런 함수는 적어도 원칙적으로 완전히 메모이제이션하거나 조회용 데이터 구조로 바꿀 수 있다. 사상인 함수와 객체인 함수 타입 사이 동등성의 본질이 바로 이것이다.

예를 들어 `Bool`에서 출발하는 순수 함수는 값 한 쌍으로 완전히 정해진다. 하나는 `False`에 대응하고 다른 하나는 `True`에 대응한다. `Bool`에서 이를테면 `Int`로 가는 가능한 모든 함수의 집합은 모든 `Int` 쌍의 집합이다. 이는 곱 `Int × Int`, 또는 표기를 조금 창의적으로 쓰면 Int<sup>2</sup>와 같다.

다른 예로 값 256개를 포함하는 C++ 타입 `char`를 살펴보자. 하스켈은 유니코드를 사용하므로 하스켈의 `Char`는 더 크다. C++ 표준 라이브러리의 일부 함수는 보통 조회를 사용해 구현한다. `isupper`나 `isspace` 같은 함수는 불리언 값 256개의 튜플과 동등한 테이블로 구현한다. 튜플은 곱 타입이므로 `bool × bool × bool × ... × bool`이라는 256개 불리언의 곱을 다루는 셈이다. 산술에서 반복된 곱이 거듭제곱을 정의한다는 것을 안다. `bool`을 자기 자신과 256번, 즉 `char`번 "곱하면" `bool`의 `char`제곱, 즉 bool<sup>char</sup>을 얻는다.

`bool`의 256-튜플로 정의한 타입에는 값이 몇 개 있을까? 정확히 2<sup>256</sup>개다. 이는 `char`에서 `bool`로 가는 서로 다른 함수의 개수이기도 하며 각 함수는 고유한 256-튜플에 대응한다. 마찬가지로 `bool`에서 `char`로 가는 함수가 256<sup>2</sup>개임을 계산할 수 있다. 이런 경우 함수 타입의 지수 표기는 완벽하게 말이 된다.

`int`나 `double`에서 출발하는 함수를 완전히 메모이제이션하고 싶지는 않을 것이다. 하지만 언제나 실용적인 것은 아니더라도 함수와 데이터 타입 사이의 동등성은 존재한다. 리스트, 문자열, 트리 같은 무한 타입도 있다. 그런 타입에서 출발하는 함수를 즉시 메모이제이션하려면 무한한 저장 공간이 필요하다. 하지만 하스켈은 지연 언어이므로 지연 평가되는 무한 데이터 구조와 함수 사이의 경계가 흐릿하다. 함수와 데이터의 이 쌍대성이 하스켈 함수 타입을 범주론적 지수 객체와 동일시하는 이유를 설명한다. 지수 객체는 *데이터*에 대한 우리의 관념에 더 가깝다.

## 데카르트 닫힌 범주

앞으로도 집합의 범주를 타입과 함수의 모형으로 사용하겠지만, 그 목적으로 사용할 수 있는 더 큰 범주 계열이 있다는 점은 언급할 만하다. 이런 범주를 *데카르트 닫힌* 범주라고 하며 **Set**은 그 한 예일 뿐이다.

데카르트 닫힌 범주는 다음을 포함해야 한다.

1.  종단 객체
2.  임의의 객체 쌍의 곱
3.  임의의 객체 쌍의 지수

지수를 반복된 곱, 어쩌면 무한히 반복된 곱으로 본다면 데카르트 닫힌 범주는 임의의 항수를 가진 곱을 지원하는 범주라고 생각할 수 있다. 특히 종단 객체는 객체 0개의 곱, 또는 어떤 객체의 0제곱으로 생각할 수 있다.

컴퓨터 과학의 관점에서 데카르트 닫힌 범주가 흥미로운 이유는 모든 타입 프로그래밍 언어의 바탕을 이루는 단순 타입 람다 대수의 모형을 제공하기 때문이다.

종단 객체와 곱에는 각각 쌍대인 시작 객체와 쌍대곱이 있다. 이 둘도 지원하고 곱이 쌍대곱에 대해 다음처럼 분배되는 데카르트 닫힌 범주를

```haskell
a × (b + c) = a × b + a × c
(b + c) × a = b × a + c × a
```

*양데카르트 닫힌* 범주라고 한다. 다음 절에서는 대표적인 예인 **Set**을 비롯한 양데카르트 닫힌 범주가 몇 가지 흥미로운 성질을 지님을 보겠다.

## 지수와 대수적 데이터 타입

함수 타입을 지수로 해석하는 방식은 대수적 데이터 타입의 체계와 아주 잘 맞는다. 고등학교 대수에서 수 0과 1, 합, 곱, 지수 사이의 관계를 나타내는 모든 기본 항등식은 어떤 양데카르트 닫힌 범주에서도 거의 그대로 성립한다. 각각 시작 객체와 종단 객체, 쌍대곱, 곱, 지수에 대응한다. 아직 이를 증명할 도구, 이를테면 수반이나 요네다 보조정리는 배우지 않았지만 귀중한 직관의 원천이므로 여기에 나열하겠다.

### 0제곱

<pre>
a<sup>0</sup> = 1
</pre>

범주론적 해석에서는 0을 시작 객체로, 1을 종단 객체로, 등호를 동형으로 바꾼다. 지수는 내부 hom-객체다. 이 지수는 시작 객체에서 임의의 객체 `a`로 가는 사상들의 집합을 나타낸다. 시작 객체의 정의에 따라 그런 사상은 정확히 하나이므로 hom-set *C(0, a)*는 한 원소 집합이다. 한 원소 집합은 **Set**의 종단 객체이므로 이 항등식은 **Set**에서 자명하게 성립한다. 여기서 말하는 바는 모든 양데카르트 닫힌 범주에서 성립한다는 것이다.

하스켈에서는 0을 `Void`로, 1을 유닛 타입 `()`로, 지수를 함수 타입으로 바꾼다. `Void`에서 임의의 타입 `a`로 가는 함수의 집합은 한 원소인 유닛 타입과 동등하다는 주장이다. 다시 말해 `Void->a` 함수는 하나뿐이다. 앞에서 본 `absurd`라는 함수다.

여기에는 두 가지 까다로운 점이 있다. 하나는 하스켈에는 실제로 값이 전혀 없는 타입이 없다는 것이다. 모든 타입은 "끝나지 않는 계산의 결과", 즉 bottom을 포함한다. 둘째로 `absurd`의 모든 구현은 무엇을 하든 아무도 실행할 수 없으므로 동등하다. `absurd`에 전달할 수 있는 값이 없다. 끝나지 않는 계산을 전달하는 데 성공한다면 그 함수도 결코 반환하지 않을 것이다!

### 1의 거듭제곱

<pre>
1<sup>a</sup> = 1
</pre>

이 항등식을 **Set**에서 해석하면 종단 객체의 정의를 다시 말한 것이 된다. 임의의 객체에서 종단 객체로 가는 사상은 유일하다. 일반적으로 `a`에서 종단 객체로 가는 내부 hom-객체는 종단 객체 자체와 동형이다.

하스켈에서는 임의의 타입 `a`에서 유닛으로 가는 함수가 하나뿐이다. 앞에서 본 `unit`이라는 함수다. `const`를 `()`에 부분 적용한 함수라고 생각할 수도 있다.

### 1제곱

<pre>
a<sup>1</sup> = a
</pre>

이는 종단 객체에서 출발하는 사상을 사용해 객체 `a`의 "원소"를 고를 수 있다는 관찰을 다시 말한 것이다. 그런 사상의 집합은 객체 자체와 동형이다. **Set**과 하스켈에서 동형은 집합 `a`의 원소와 그 원소를 고르는 함수 `()->a` 사이에 있다.

### 합의 지수

<pre>
a<sup>b+c</sup> = a<sup>b</sup> × a<sup>c</sup>
</pre>

범주론적으로 이는 두 객체의 쌍대곱에서 출발하는 지수가 두 지수의 곱과 동형이라는 말이다. 하스켈에서 이 대수적 항등식은 매우 실용적으로 해석된다. 두 타입의 합에서 출발하는 함수가 각 타입에서 출발하는 함수의 쌍과 동등하다고 말해 준다. 이는 합에 대한 함수를 정의할 때 사용하는 경우 분석일 뿐이다. `case` 문을 포함한 함수 정의 하나를 쓰는 대신 보통 각 타입 생성자를 따로 처리하는 둘 이상의 함수로 나눈다. 예를 들어 합 타입 `(Either Int Double)`에서 출발하는 함수를 보자.

```haskell
f :: Either Int Double -> String
```

각각 `Int`와 `Double`에서 출발하는 함수의 쌍으로 정의할 수 있다.

```haskell
f (Left n)  = if n < 0 then "Negative int" else "Positive int"
f (Right x) = if x < 0.0 then "Negative double" else "Positive double"
```

여기서 `n`은 `Int`이고 `x`는 `Double`이다.

### 지수의 지수

<pre>
(a<sup>b</sup>)<sup>c</sup> = a<sup>b×c</sup>
</pre>

이는 커링을 오로지 지수 객체로 표현한 것이다. 함수를 반환하는 함수는 곱에서 출발하는 함수, 즉 두 인자 함수와 동등하다.

### 곱 위의 지수

<pre>
(a × b)<sup>c</sup> = a<sup>c</sup> × b<sup>c</sup>
</pre>

하스켈에서는 쌍을 반환하는 함수가 각각 쌍의 원소 하나를 만드는 함수의 쌍과 동등하다는 뜻이다.

이 단순한 고등학교 대수 항등식들을 범주론으로 끌어올려 함수형 프로그래밍에 실제로 응용할 수 있다는 사실은 놀랍기 그지없다.

## Curry-Howard 동형

논리와 대수적 데이터 타입 사이의 대응은 이미 언급했다. `Void` 타입과 유닛 타입 `()`는 거짓과 참에 대응한다. 곱 타입과 합 타입은 논리곱 ∧(AND)과 논리합 ⋁(OR)에 대응한다. 이 체계에서 방금 정의한 함수 타입은 논리적 함의 ⇒에 대응한다. 다시 말해 타입 `a->b`는 "a이면 b"라고 읽을 수 있다.

Curry-Howard 동형에 따르면 모든 타입은 참이거나 거짓일 수 있는 명제, 즉 진술이나 판단으로 해석할 수 있다. 타입에 값이 있으면 그런 명제를 참으로, 없으면 거짓으로 본다. 특히 논리적 함의는 그에 대응하는 함수 타입에 값이 있을 때, 즉 그 타입의 함수가 존재할 때 참이다. 따라서 함수의 구현은 정리의 증명이다. 프로그램을 작성하는 일은 정리를 증명하는 일과 동등하다. 몇 가지 예를 보자.

함수 객체의 정의에서 도입한 함수 `eval`을 보자. 시그니처는 다음과 같다.

```haskell
eval :: ((a -> b), a) -> b
```

함수와 그 인자로 이루어진 쌍을 받아 적절한 타입의 결과를 만든다. 다음 사상의 하스켈 구현이다.

```haskell
eval :: (a⇒b) × a -> b
```

이 사상은 함수 타입 `a⇒b`, 즉 지수 객체 b<sup>a</sup>를 정의한다. Curry-Howard 동형을 사용해 이 시그니처를 논리 명제로 옮겨 보자.

```haskell
((a ⇒ b) ∧ a) ⇒ b
```

이 명제는 이렇게 읽는다. `a`에서 `b`가 따라 나온다는 것이 참이고 `a`도 참이라면 `b`는 참이어야 한다. 직관적으로 완벽하게 말이 되며, 고대부터 *modus ponens*, 즉 전건 긍정으로 알려져 있다. 함수를 구현해서 이 정리를 증명할 수 있다.

```haskell
eval :: ((a -> b), a) -> b
eval (f, x) = f x
```

`a`를 받아 `b`를 반환하는 함수 `f`와 `a` 타입의 구체적인 값 `x`로 이루어진 쌍을 주면, `f`를 `x`에 적용하기만 해서 `b` 타입의 구체적인 값을 만들 수 있다. 이 함수를 구현함으로써 타입 `((a -> b), a) -> b`에 값이 있음을 보였다. 따라서 우리의 논리에서 전건 긍정은 참이다.

명백히 거짓인 명제는 어떨까? 예를 들어 `a` 또는 `b`가 참이면 `a`가 참이어야 한다고 하자.

```haskell
a ⋁ b ⇒ a
```

이는 명백히 틀렸다. 거짓인 `a`와 참인 `b`를 고를 수 있고, 이것이 반례가 되기 때문이다.

Curry-Howard 동형을 사용해 이 명제를 함수 시그니처로 옮기면 다음을 얻는다.

```haskell
Either a b -> a
```

아무리 애써도 이 함수는 구현할 수 없다. `Right` 값으로 호출되면 `a` 타입의 값을 만들어 낼 수 없기 때문이다. 순수 함수에 대해 이야기하고 있음을 기억하자.

마지막으로 `absurd` 함수의 의미에 이른다.

```haskell
absurd :: Void -> a
```

`Void`를 거짓으로 옮기면 다음을 얻는다.

```haskell
 false ⇒ a
```

거짓에서는 무엇이든 따라 나온다. 이를 *ex falso quodlibet*, 즉 폭발 원리라고 한다. 이 명제, 즉 함수에 대한 가능한 하스켈 증명, 즉 구현은 다음과 같다.

```haskell
absurd (Void a) = absurd a
```

여기서 `Void`는 다음처럼 정의한다.

```haskell
newtype Void = Void Void
```

늘 그렇듯 `Void` 타입은 까다롭다. 이 정의로는 값을 구성할 수 없다. 하나를 구성하려면 이미 하나를 제공해야 하기 때문이다. 따라서 함수 `absurd`는 절대로 호출될 수 없다.

모두 흥미로운 예지만 Curry-Howard 동형에 실용적인 측면도 있을까? 일상적인 프로그래밍에서는 아마 없을 것이다. 하지만 Agda나 Coq처럼 Curry-Howard 동형을 활용해 정리를 증명하는 프로그래밍 언어가 있다.

컴퓨터는 수학자가 작업하도록 돕는 데 그치지 않고 수학의 토대 자체를 혁신하고 있다. 이 분야의 최신 인기 연구 주제는 호모토피 타입 이론이라고 하며 타입 이론에서 뻗어 나왔다. 불리언, 정수, 곱과 쌍대곱, 함수 타입 등으로 가득하다. 조금의 의심도 없애려는 듯 이 이론은 Coq와 Agda로 정식화되고 있다. 컴퓨터는 여러 방식으로 세상을 혁신하고 있다.
