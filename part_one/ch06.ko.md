# 단순한 대수적 데이터 타입 {#simple-algebraic-data-types}

우리는 타입을 결합하는 두 가지 기본 방법, 곱과 쌍대곱을 보았다. 일상적인 프로그래밍에서 쓰이는 많은 데이터 구조가 이 두 메커니즘만으로 만들어질 수 있다는 사실이 드러난다. 이 사실에는 중요한 실용적 결과가 있다. 데이터 구조의 많은 성질은 합성 가능하다. 예를 들어 기본 타입의 값들을 동등성으로 비교하는 방법을 알고 있고, 이 비교를 곱 타입과 합 타입으로 일반화하는 방법을 알고 있다면, 복합 타입에 대한 동등성 연산자를 자동으로 유도할 수 있다. 하스켈에서는 복합 타입의 큰 부분집합에 대해 동등성, 비교, 문자열과의 변환 등을 자동으로 유도할 수 있다.

프로그래밍에서 나타나는 곱 타입과 합 타입을 더 가까이 살펴보자.

## 곱 타입

프로그래밍 언어에서 두 타입의 곱을 표준적으로 구현한 것은 쌍이다. 하스켈에서 쌍은 원시 타입 생성자이고, C++에서는 표준 라이브러리에 정의된 비교적 복잡한 템플릿이다.

![](images/pair.jpg)

쌍은 엄밀하게 교환적이지 않다. `(Int, Bool)` 쌍을 `(Bool, Int)` 쌍 대신 사용할 수는 없다. 둘이 같은 정보를 담고 있더라도 말이다. 하지만 동형까지는 교환적이다. 그 동형은 `swap` 함수가 제공한다. 이 함수는 자기 자신의 역이다.

```haskell
swap :: (a, b) -> (b, a)
swap (x, y) = (y, x)
```

두 쌍은 같은 데이터를 저장하는 형식만 다르게 사용하는 것이라고 생각할 수 있다. 빅 엔디언과 리틀 엔디언의 차이와 비슷하다.

쌍 안에 쌍을 중첩하면 임의의 수의 타입을 곱으로 결합할 수 있지만, 더 쉬운 방법이 있다. 중첩된 쌍은 튜플과 동등하다. 이는 쌍을 중첩하는 여러 방식이 서로 동형이라는 사실의 결과다. 세 타입 `a`, `b`, `c`를 이 순서로 곱으로 결합하고 싶다면 두 가지 방식이 있다.

```haskell
((a, b), c)
```

또는 다음과 같다.

```haskell
(a, (b, c))
```

이 타입들은 다르다. 하나를 다른 하나를 기대하는 함수에 넘길 수는 없다. 하지만 그 원소들은 일대일 대응한다. 하나를 다른 하나로 보내는 함수가 있다.

```haskell
alpha :: ((a, b), c) -> (a, (b, c))
alpha ((x, y), z) = (x, (y, z))
```

그리고 이 함수는 가역적이다.

```haskell
alpha_inv :: (a, (b, c)) -> ((a, b), c)
alpha_inv  (x, (y, z)) = ((x, y), z)
```

따라서 이것은 동형이다. 이들은 같은 데이터를 다시 포장하는 서로 다른 방식일 뿐이다.

곱 타입의 생성을 타입 위의 이항 연산으로 해석할 수 있다. 그 관점에서 위 동형은 모노이드에서 보았던 결합법칙과 매우 비슷해 보인다.

```haskell
(a * b) * c = a * (b * c)
```

다만 모노이드의 경우 두 곱의 합성 방식이 같았지만, 여기서는 "동형까지" 같을 뿐이다.

동형을 받아들이고 엄격한 동등성을 고집하지 않는다면 더 나아갈 수 있다. unit 타입 `()`이 곱의 단위라는 것을 보일 수 있다. 1이 곱셈의 단위인 것과 같다. 실제로 어떤 타입 `a`의 값과 unit을 짝짓는 것은 아무 정보도 더하지 않는다. 다음 타입은:

```haskell
(a, ())
```

`a`와 동형이다. 동형은 다음과 같다.

```haskell
rho :: (a, ()) -> a
rho (x, ()) = x
```

```haskell
rho_inv :: a -> (a, ())
rho_inv x = (x, ())
```

이 관찰은 **Set**, 즉 집합의 범주가 *모노이드 범주*라고 말함으로써 형식화할 수 있다. 객체들을 곱할 수 있다는 의미에서, 여기서는 데카르트 곱을 취할 수 있다는 의미에서, 범주이면서 동시에 모노이드인 범주다. 모노이드 범주에 대해서는 나중에 더 이야기하고 완전한 정의를 제시하겠다.

하스켈에는 곱 타입을 정의하는 더 일반적인 방식이 있다. 특히 곧 보겠지만, 합 타입과 결합될 때 그렇다. 이 방식은 여러 인자를 받는 이름 붙은 생성자를 사용한다. 예를 들어 쌍은 다음처럼 다르게 정의할 수 있다.

```haskell
data Pair a b = P a b
```

여기서 `Pair a b`는 두 타입 `a`와 `b`로 매개변수화된 타입의 이름이고, `P`는 데이터 생성자의 이름이다. `Pair` 타입 생성자에 두 타입을 넘겨 쌍 타입을 정의한다. 생성자 `P`에 적절한 타입의 두 값을 넘겨 쌍 값을 만든다. 예를 들어 `String`과 `Bool`의 쌍으로 값 `stmt`를 정의해 보자.

```haskell
stmt :: Pair String Bool
stmt = P "This statements is" False
```

첫 줄은 타입 선언이다. 제네릭 정의의 `a`와 `b`를 `String`과 `Bool`로 바꿔 타입 생성자 `Pair`를 사용한다. 둘째 줄은 구체적인 문자열과 구체적인 불리언을 데이터 생성자 `P`에 넘겨 실제 값을 정의한다. 타입 생성자는 타입을 만들기 위해 사용되고, 데이터 생성자는 값을 만들기 위해 사용된다.

하스켈에서는 타입 생성자와 데이터 생성자의 이름 공간이 분리되어 있으므로, 다음처럼 같은 이름이 둘 모두에 쓰이는 것을 자주 보게 된다.

```haskell
data Pair a b = Pair a b
```

눈을 가늘게 뜨고 보면 내장 쌍 타입도 이런 선언의 변형으로 볼 수 있다. 이름 `Pair`가 이항 연산자 `(,)`로 바뀐 것뿐이다. 실제로 `(,)`를 다른 이름 붙은 생성자처럼 사용해 전위 표기법으로 쌍을 만들 수 있다.

```haskell
stmt = (,) "This statement is" False
```

마찬가지로 `(,,)`를 사용해 triple을 만들 수 있고, 계속 이어진다.

제네릭 쌍이나 튜플을 사용하는 대신 다음처럼 구체적인 이름 붙은 곱 타입을 정의할 수도 있다.

```haskell
data Stmt = Stmt String Bool
```

이것은 그저 `String`과 `Bool`의 곱이지만, 자기 이름과 생성자가 주어져 있다. 이런 선언 방식의 장점은 같은 내용을 가지지만 의미와 기능이 다르고 서로 대체될 수 없는 많은 타입을 정의할 수 있다는 데 있다.

튜플과 여러 인자 생성자를 사용한 프로그래밍은 지저분하고 오류가 나기 쉬워질 수 있다. 어떤 구성 요소가 무엇을 나타내는지 추적해야 하기 때문이다. 구성 요소에 이름을 붙이는 편이 더 나을 때가 많다. 이름 붙은 필드를 가진 곱 타입을 하스켈에서는 레코드라고 부르고, C에서는 `struct`라고 부른다.

## 레코드

간단한 예를 보자. 화학 원소를 하나의 데이터 구조로 표현하고 싶다. 이름과 기호라는 두 문자열, 그리고 원자 번호라는 정수를 결합하면 된다. 튜플 `(String, String, Int)`를 사용하고 어느 구성 요소가 무엇을 나타내는지 기억할 수도 있다. 구성 요소는 패턴 매칭으로 추출할 것이다. 예를 들어 원소의 기호가 그 이름의 접두사인지 확인하는 함수는 다음과 같다. **He**가 **Helium**의 접두사인 것처럼 말이다.

```haskell
startsWithSymbol :: (String, String, Int) -> Bool
startsWithSymbol (name, symbol, _) = isPrefixOf symbol name
```

이 코드는 오류가 나기 쉽고 읽고 유지보수하기도 어렵다. 레코드를 정의하는 편이 훨씬 낫다.

```haskell
data Element = Element { name         :: String
                       , symbol       :: String
                       , atomicNumber :: Int }
```

두 표현은 동형이다. 서로의 역인 다음 두 변환 함수가 그 증거다.

```haskell
tupleToElem :: (String, String, Int) -> Element
tupleToElem (n, s, a) = Element { name = n
                                , symbol = s
                                , atomicNumber = a }
```

```haskell
elemToTuple :: Element -> (String, String, Int)
elemToTuple e = (name e, symbol e, atomicNumber e)
```

레코드 필드의 이름은 그 필드에 접근하는 함수로도 쓰인다는 점에 주목하자. 예를 들어 `atomicNumber e`는 `e`에서 `atomicNumber` 필드를 가져온다. 우리는 `atomicNumber`를 다음 타입의 함수로 사용한다.

```haskell
atomicNumber :: Element -> Int
```

`Element`에 레코드 문법을 사용하면 `startsWithSymbol` 함수는 더 읽기 쉬워진다.

```haskell
startsWithSymbol :: Element -> Bool
startsWithSymbol e = isPrefixOf (symbol e) (name e)
```

함수 `isPrefixOf`를 백틱으로 감싸 중위 연산자로 바꾸는 하스켈의 기법을 사용하면, 거의 문장처럼 읽히게 만들 수도 있다.

```haskell
startsWithSymbol e = symbol e `isPrefixOf` name e
```

이 경우 괄호는 생략할 수 있다. 중위 연산자는 함수 호출보다 낮은 우선순위를 가지기 때문이다.

## 합 타입

집합의 범주에서 곱이 곱 타입을 낳듯이, 쌍대곱은 합 타입을 낳는다. 하스켈에서 합 타입의 표준 구현은 다음과 같다.

```haskell
data Either a b = Left a | Right b
```

쌍과 마찬가지로 `Either`도 동형까지 교환적이고, 중첩될 수 있으며, 중첩 순서는 동형까지 중요하지 않다. 예를 들어 triple에 해당하는 합을 다음처럼 정의할 수 있다.

```haskell
data OneOfThree a b c = Sinistral a | Medial b | Dextral c
```

이런 식이다.

**Set**은 쌍대곱에 대해서도 대칭 모노이드 범주라는 사실이 드러난다. 이항 연산의 역할은 서로소 합이 맡고, 단위 원소의 역할은 시작 객체가 맡는다. 타입의 관점에서는 `Either`가 모노이드 연산자이고, 거주자가 없는 타입 `Void`가 그 중립 원소다. `Either`를 덧셈으로, `Void`를 0으로 생각할 수 있다. 실제로 합 타입에 `Void`를 더해도 내용은 바뀌지 않는다. 예를 들어:

```
Either a Void
```

는 `a`와 동형이다. 이 타입의 `Right` 버전을 만들 방법이 없기 때문이다. `Void` 타입의 값이 없기 때문이다. `Either a Void`의 유일한 거주자들은 `Left` 생성자를 사용해 만들어지고, 타입 `a`의 값을 감쌀 뿐이다. 따라서 기호적으로 `a + 0 = a`다.

합 타입은 하스켈에서는 꽤 흔하지만, C++에서 그에 해당하는 union이나 variant는 훨씬 덜 흔하다. 이유가 몇 가지 있다.

우선 가장 단순한 합 타입은 열거형일 뿐이며, C++에서는 `enum`을 사용해 구현된다. 하스켈 합 타입:

```haskell
data Color = Red | Green | Blue
```

에 해당하는 C++는 다음과 같다.

```cpp
enum { Red, Green, Blue };
```

더 단순한 합 타입:

```haskell
data Bool = True | False
```

은 C++의 원시 타입 `bool`이다.

값의 존재 여부를 인코딩하는 단순한 합 타입은 C++에서 빈 문자열, 음수, 널 포인터 같은 특별한 요령과 "불가능한" 값들을 사용해 여러 방식으로 구현된다. 이런 선택성은 의도적인 것이라면 하스켈에서 `Maybe` 타입으로 표현된다.

```haskell
data Maybe a = Nothing | Just a
```

`Maybe` 타입은 두 타입의 합이다. 두 생성자를 개별 타입으로 분리해 보면 알 수 있다. 첫 번째는 다음과 같을 것이다.

```haskell
data NothingType = Nothing
```

이것은 `Nothing`이라는 값 하나를 가진 열거형이다. 다시 말해 unit 타입 `()`과 동등한 한 원소 타입이다. 두 번째 부분은:

```haskell
data JustType a = Just a
```

타입 `a`를 감싼 것일 뿐이다. 우리는 `Maybe`를 다음처럼 인코딩할 수도 있었다.

```haskell
data Maybe a = Either () a
```

더 복잡한 합 타입은 C++에서 포인터를 사용해 흉내 내는 경우가 많다. 포인터는 null이거나 특정 타입의 값을 가리킬 수 있다. 예를 들어 하스켈 리스트 타입은 재귀적 합 타입으로 다음처럼 정의될 수 있다.

```haskell
List a = Nil | Cons a (List a)
```

이를 C++로 번역할 때 빈 리스트를 구현하기 위해 널 포인터 요령을 사용할 수 있다.

```cpp
template<class A> 
class List {
    Node<A> * _head;
public:
    List() : _head(nullptr) {}  // Nil
    List(A a, List<A> l)        // Cons
      : _head(new Node<A>(a, l))
    {}
};
```

하스켈의 두 생성자 `Nil`과 `Cons`가 유사한 인자를 가진 두 개의 오버로드된 `List` 생성자로 번역된다는 점에 주목하자. `Nil`에는 인자가 없고, `Cons`에는 값과 리스트가 있다. `List` 클래스는 합 타입의 두 구성 요소를 구분하기 위한 태그가 필요 없다. 대신 `_head`의 특별한 값 `nullptr`를 사용해 `Nil`을 인코딩한다.

하지만 하스켈 타입과 C++ 타입의 주된 차이는 하스켈 데이터 구조가 불변이라는 점이다. 특정 생성자로 객체를 만들면, 그 객체는 어떤 생성자가 사용되었고 어떤 인자가 전달되었는지 영원히 기억한다. 따라서 `Just "energy"`로 만들어진 `Maybe` 객체가 `Nothing`으로 바뀌는 일은 없다. 마찬가지로 빈 리스트는 영원히 비어 있고, 세 원소의 리스트는 언제나 같은 세 원소를 가진다.

구성을 되돌릴 수 있게 만드는 것은 바로 이 불변성이다. 객체가 주어지면, 언제나 그 객체를 만들 때 사용한 부분들로 분해할 수 있다. 이 분해는 패턴 매칭으로 이루어지고, 생성자를 패턴으로 재사용한다. 생성자 인자가 있다면 변수나 다른 패턴으로 대체된다.

`List` 데이터 타입에는 두 생성자가 있으므로, 임의의 `List`를 분해할 때는 그 생성자들에 대응하는 두 패턴을 사용한다. 하나는 빈 `Nil` 리스트와 맞고, 다른 하나는 `Cons`로 만들어진 리스트와 맞는다. 예를 들어 `List` 위의 단순한 함수 정의는 다음과 같다.

```haskell
maybeTail :: List a -> Maybe (List a)
maybeTail Nil = Nothing
maybeTail (Cons _ t) = Just t
```

`maybeTail` 정의의 첫 부분은 `Nil` 생성자를 패턴으로 사용하고 `Nothing`을 반환한다. 둘째 부분은 `Cons` 생성자를 패턴으로 사용한다. 첫 번째 생성자 인자는 관심이 없으므로 와일드카드로 바꾼다. `Cons`의 두 번째 인자는 변수 `t`에 바인딩된다. 엄밀히 말하면 한 번 표현식에 바인딩된 변수는 변하지 않지만, 나는 이것들을 변수라고 부르겠다. 반환값은 `Just t`다. 이제 당신의 `List`가 어떻게 만들어졌는지에 따라 두 절 중 하나와 맞을 것이다. `Cons`를 사용해 만들어졌다면, 전달되었던 두 인자를 되찾고 첫 번째는 버린다.

더 정교한 합 타입은 C++에서 다형 클래스 계층으로 구현된다. 공통 조상을 가진 클래스들의 가족은 하나의 variant 타입으로 이해될 수 있고, 이때 vtable이 숨겨진 태그 역할을 한다. 하스켈에서 생성자에 대한 패턴 매칭과 특수화된 코드 호출로 처리할 일을, C++에서는 vtable 포인터를 기반으로 가상 함수 호출을 디스패치함으로써 처리한다.

C++에서 `union`을 합 타입으로 사용하는 일은 드물다. union에 무엇을 넣을 수 있는지에 심한 제한이 있기 때문이다. 복사 생성자를 가진다는 이유로 `std::string`조차 union에 넣을 수 없다.

## 타입의 대수

곱 타입과 합 타입은 각각 따로도 다양한 유용한 데이터 구조를 정의하는 데 사용할 수 있지만, 진짜 힘은 둘을 결합할 때 나온다. 다시 한 번 우리는 합성의 힘을 부르고 있다.

지금까지 발견한 것을 정리해 보자. 타입 시스템의 바탕에는 두 개의 교환 모노이드 구조가 있다. 중립 원소로 `Void`를 갖는 합 타입과, 중립 원소로 unit 타입 `()`을 갖는 곱 타입이다. 우리는 이것들을 덧셈과 곱셈에 비유하고 싶다. 이 비유에서 `Void`는 0에 대응하고, unit `()`은 1에 대응한다.

이 비유를 어디까지 밀고 갈 수 있는지 보자. 예를 들어 0을 곱하면 0이 되는가? 다시 말해 한 구성 요소가 `Void`인 곱 타입은 `Void`와 동형인가? 예컨대 `Int`와 `Void`의 쌍을 만들 수 있을까?

쌍을 만들려면 값이 두 개 필요하다. 정수는 쉽게 만들 수 있지만, `Void` 타입의 값은 없다. 따라서 임의의 타입 `a`에 대해 `(a, Void)` 타입은 거주자가 없다. 값이 없으므로 `Void`와 동등하다. 다시 말해 `a*0 = 0`이다.

덧셈과 곱셈을 연결하는 또 다른 것은 분배법칙이다.

```haskell
a * (b + c) = a * b + a * c
```

곱 타입과 합 타입에서도 이것이 성립할까? 그렇다. 늘 그렇듯 동형까지 성립한다. 왼쪽은 다음 타입에 대응한다.

```haskell
(a, Either b c)
```

오른쪽은 다음 타입에 대응한다.

```haskell
Either (a, b) (a, c)
```

한 방향으로 변환하는 함수는 다음과 같다.

```haskell
prodToSum :: (a, Either b c) -> Either (a, b) (a, c)
prodToSum (x, e) = 
    case e of
      Left  y -> Left  (x, y)
      Right z -> Right (x, z)
```

다른 방향으로 가는 함수는 다음과 같다.

```haskell
sumToProd :: Either (a, b) (a, c) -> (a, Either b c)
sumToProd e = 
    case e of
      Left  (x, y) -> (x, Left  y)
      Right (x, z) -> (x, Right z)
```

`case of` 문은 함수 안에서 패턴 매칭을 할 때 사용된다. 각 패턴 뒤에는 화살표와, 그 패턴이 맞을 때 평가할 표현식이 온다. 예를 들어 `prodToSum`을 다음 값으로 호출하면:

```haskell
prod1 :: (Int, Either String Float)
prod1 = (2, Left "Hi!")
```

`case e of` 안의 `e`는 `Left "Hi!"`와 같을 것이다. 이것은 패턴 `Left y`와 맞고, `"Hi!"`가 `y`에 대입된다. `x`는 이미 `2`와 맞았으므로, `case of` 절의 결과이자 전체 함수의 결과는 예상대로 `Left (2, "Hi!")`가 된다.

이 두 함수가 서로의 역이라는 것을 증명하지는 않겠지만, 생각해 보면 반드시 그래야 한다. 두 데이터 구조의 내용을 사소하게 다시 포장하고 있을 뿐이다. 같은 데이터이고 형식만 다르다.

수학자들은 이렇게 얽힌 두 모노이드에 이름을 붙였다. *반환*(semiring)이라고 부른다. 완전한 *환*(ring)은 아니다. 타입의 뺄셈을 정의할 수 없기 때문이다. 그래서 semiring은 때때로 *rig*라고 불리는데, 이는 "ring에서 n(negative)을 뺀 것"이라는 말장난이다. 그 점을 제외하면 자연수처럼 환을 이루는 대상에 대한 명제를 타입에 대한 명제로 번역해 꽤 많은 것을 얻을 수 있다. 흥미로운 항목 몇 가지를 담은 번역표는 다음과 같다.

  <th>Numbers</th>
  <th>Types</th>
</tr>

  <td>0</td>
  <td>`Void`</td>
</tr>

  <td>1</td>
  <td>`()`</td>

  <td>a + b</td>
  <td>`Either a b = Left a | Right b`</td>

리스트 타입은 꽤 흥미롭다. 방정식의 해로 정의되기 때문이다. 우리가 정의하는 타입이 방정식의 양쪽에 모두 나타난다.

```haskell
List a = Nil | Cons a (List a)
```

늘 하던 치환을 하고, `List a`를 `x`로 바꾸면 다음 방정식을 얻는다.

```haskell
x = 1 + a * x
```

타입을 빼거나 나눌 수 없으므로 전통적인 대수적 방법으로는 풀 수 없다. 하지만 치환을 연속적으로 시도할 수 있다. 오른쪽의 `x`를 계속 `(1 + a*x)`로 바꾸고 분배법칙을 사용한다. 그러면 다음 급수로 이어진다.

```haskell
x = 1 + a*x
x = 1 + a*(1 + a*x) = 1 + a + a*a*x
x = 1 + a + a*a*(1 + a*x) = 1 + a + a*a + a*a*a*x
...
x = 1 + a + a*a + a*a*a + a*a*a*a...
```

결국 곱, 즉 튜플들의 무한 합을 얻는다. 이는 리스트가 비어 있거나 `1`, 하나짜리이거나 `a`, 쌍이거나 `a*a`, triple이거나 `a*a*a` 등으로 해석될 수 있다. 음, 이것이 바로 리스트다. `a`들의 문자열이다.

리스트에는 이보다 훨씬 많은 것이 있고, functor와 고정점에 대해 배운 뒤 리스트와 다른 재귀적 데이터 구조로 돌아올 것이다.

기호 변수를 가진 방정식을 푸는 것, 이것이 대수다. 그래서 이런 타입들이 대수적 데이터 타입이라는 이름을 얻었다.

마지막으로 타입의 대수에 대한 매우 중요한 해석 하나를 언급해야겠다. 두 타입 `a`와 `b`의 곱은 타입 `a`의 값 *그리고* 타입 `b`의 값을 모두 포함해야 한다. 이는 두 타입 모두 거주자가 있어야 한다는 뜻이다. 반면 두 타입의 합은 타입 `a`의 값 *또는* 타입 `b`의 값을 포함하므로, 둘 중 하나에만 거주자가 있으면 충분하다. 논리적 *and*와 *or*도 반환을 이루며, 이것 역시 타입 이론으로 사상될 수 있다.

<tr>
  <th>Logic</th>
  <th>Types</th>
</tr>
<tr>
  <td>false</td>
  <td>`Void`</td>
</tr>
<tr>
  <td>true</td>
  <td>`()`</td>
</tr>
<tr>
  <td>a || b</td>
  <td>`Either a b = Left a | Right b`</td>
</tr>
<tr>
  <td>a && b</td>
  <td>`(a, b)`</td>
</tr>
</table>

이 비유는 더 깊이 이어지고, 논리와 타입 이론 사이의 커리-하워드 동형의 기초가 된다. 함수 타입에 대해 이야기할 때 다시 돌아오겠다.

## 연습문제

1. `Maybe a`와 `Either () a` 사이의 동형을 보여라.
2. 하스켈로 정의된 다음 합 타입이 있다.

```haskell
data Shape = Circle Float
               | Rect Float Float
```

`Shape`에 작용하는 `area` 같은 함수를 정의하고 싶을 때, 두 생성자에 대한 패턴 매칭으로 정의한다.

```haskell
area :: Shape -> Float
    area (Circle r) = pi * r * r
    area (Rect d h) = d * h
```

C++ 또는 Java에서 `Shape`를 인터페이스로 구현하고 `Circle`과 `Rect` 두 클래스를 만들어라. `area`를 가상 함수로 구현하라.

3. 앞 예제를 계속하자. `Shape`의 둘레를 계산하는 새 함수 `circ`를 쉽게 추가할 수 있다. `Shape`의 정의를 건드리지 않고도 할 수 있다.

```haskell
circ :: Shape -> Float
    circ (Circle r) = 2.0 * pi * r
    circ (Rect d h) = 2.0 * (d + h)
```

C++ 또는 Java 구현에 `circ`를 추가하라. 원래 코드의 어떤 부분을 건드려야 했는가?

4. 더 이어서, `Shape`에 새 모양 `Square`를 추가하고 필요한 모든 갱신을 하라. 하스켈과 C++ 또는 Java에서 각각 어떤 코드를 건드려야 했는가? 하스켈 프로그래머가 아니더라도 수정 사항은 꽤 분명할 것이다.

5. 타입에 대해 `a + a = 2 * a`가 성립함을 보여라. 동형까지 성립하면 된다. 번역표에 따르면 `2`가 `Bool`에 대응한다는 것을 기억하라.
